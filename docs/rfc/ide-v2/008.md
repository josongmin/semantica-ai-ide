1. Summary

Multi-Agent Orchestrator Surface는 여러 agent를 병렬로 계획/실행/검토/수렴시키는 운영면이다.

기존 AI coding UX:
single prompt → single agent → single patch

Semantica DevOS:
intent → task decomposition → multi-agent allocation → parallel execution → evidence review → convergence → approval

이 surface의 목적은 agent를 채팅창 안의 텍스트 엔티티가 아니라, 운영 가능한 작업자 집합으로 승격하는 것이다.

2. Problem Statement

단일 agent 모델의 한계:

문제 설명
작업 분해 약함 큰 작업을 구조적으로 나누기 어려움
병렬성 부족 search, impact, patch, test를 동시에 수행 못함
실패 복원 약함 한 경로 실패 시 전체 흐름 중단
reasoning 투명성 부족 어떤 agent가 무엇을 담당하는지 불명확
충돌 관리 부족 여러 patch나 file edit 충돌을 체계적으로 제어 못함

3. Goals

3-1. Role-Based Agent 운영

agent를 역할 단위로 분리: Planner, Search, Impact, Patch, Test, Review, Repair

3-2. Task DAG 시각화

작업을 DAG로 표현하고 agent 할당 상태를 표시

3-3. Concurrency Visibility

병렬 실행, 대기, 충돌, dependency blocking 상태를 드러냄

3-4. Convergence UX

여러 agent 결과를 비교하고 하나의 승인 후보로 수렴

3-5. Approval / Policy Integration

위험 작업, destructive edit, merge 후보를 사용자 승인 흐름과 연결

4. Design Principles

4-1. Agent는 채팅 메시지가 아니라 실행 주체임

UI에서 agent는 단순 말풍선이 아니라 아래 상태를 가진다:
assigned task, current step, active context, running tool/job, produced artifacts, pending approval, final outcome

4-2. Plan과 Execution을 분리함

Plan Layer → Task DAG / dependency / ownership
Execution Layer → agent run / job / status / evidence

4-3. Evidence 없는 convergence 금지

수렴은 impact, security delta, test result, complexity delta, scope size, proof verdict를 사용함.

4-4. Orchestrator는 직접 엔진을 호출하지 않음

반드시 Integration Kernel 하위 계층(Query Gateway, Event Bridge, Policy Translator)을 통해 동작함.

7. Core Domain Model (canonical)

7-1. OrchestratorRun
interface OrchestratorRun {
  id: string
  intent: string
  status: "planning" | "running" | "converging" | "awaiting_approval" | "completed" | "failed"
  createdAt: number
  updatedAt: number
  planId: string
  activeAgentIds: string[]
  candidateIds: string[]
}

7-2. TaskNode
interface TaskNode {
  id: string
  title: string
  type: "search" | "analysis" | "patch" | "test" | "review" | "repair"
  status: "queued" | "ready" | "running" | "blocked" | "completed" | "failed"
  priority: "low" | "normal" | "high" | "critical"
  dependsOn: string[]
  assignedAgentId?: string
  outputs?: string[]
}

7-3. AgentUnit (canonical)
interface AgentUnit {
  id: string
  role: "planner" | "search" | "impact" | "patch" | "test" | "review" | "repair"
  name: string
  status: "idle" | "assigned" | "running" | "waiting" | "blocked" | "failed" | "completed"
  currentTaskId?: string
  currentStep?: string
  progress?: number
}

7-4. CandidateArtifact
interface CandidateArtifact {
  id: string
  kind: "patch" | "analysis_bundle" | "review_bundle" | "repair_proposal"
  sourceAgentId: string
  relatedTaskId: string
  patchId?: string
  reviewEvidenceId?: string
  score?: number
  status: "draft" | "ready" | "selected" | "discarded"
}

8. ViewModel Contract

interface MultiAgentOrchestratorViewModel {
  orchestrator: OrchestratorRunView
  tasks: TaskNodeView[]
  agents: AgentUnitView[]
  candidates: CandidateArtifactView[]
  approvals: ApprovalItemView[]
  convergence?: ConvergenceView
}

interface ConvergenceView {
  mode: "single_candidate" | "multi_candidate_compare" | "repair_loop"
  selectedCandidateId?: string
  candidateScores: {
    candidateId: string
    score: number
    reason: string[]
  }[]
}

12. Concurrency / Conflict Model

Conflict 설명
file write conflict 동일 파일 수정 경쟁
symbol conflict 동일 심볼 수정 경쟁
dependency block 선행 task 미완료
policy block 승인 대기
resource contention tool/job 슬롯 부족

표시 규칙:
- blocked task는 붉은 경계선
- waiting task는 점선
- conflict edge는 별도 강조

13. State Model Mapping (5-Layer — RFC-010)

Layer 적용

S4 Domain State tasks, agents, candidates, approvals
S5 Ephemeral hover, drag, transient loading

14. Acceptance Criteria

구조:
- Query Gateway / Event Bridge / Policy Translator만 사용
- agent runtime internal model을 직접 렌더링하지 않음
- candidate 비교는 normalized ViewModel 위에서만 수행

기능:
- task DAG 표시
- agent fleet 상태 표시
- candidate compare / select
- approval queue 통합
- failure / blocked / retry 시각화

확장:
- role 추가 가능
- speculative execution 모드 추가 가능
- distributed agent backend로 확장 가능

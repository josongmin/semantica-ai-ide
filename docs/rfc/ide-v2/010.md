1. Summary

이 문서는 Semantica DevOS 전체 Surface의 상태 모델을 고정하는 SSOT다.

DevOS는 6개의 UI Surface로 구성된다 (RFC-009 참조).
각 Surface가 독립 state 모델을 가지면 시스템은 빠르게 붕괴한다.

따라서 DevOS는 공통 상태 계약(Cross-Surface State Contract)을 가진다.

2. State Design Principles

2.1 Single Source of Truth

각 state는 정확히 하나의 owner surface만 가진다.

2.2 Event Projection

Surface state는 직접 변경되지 않는다.

event
↓
state projection
↓
view model

2.3 Immutable Domain State

Domain state는 immutable snapshot 기반이다.

2.4 Surface Isolation

Surface는 서로 state를 직접 변경할 수 없다.

3. DevOS State Layers

DevOS는 5-Layer State Architecture를 사용한다.

Layer 역할
S1 Persistent Layout
S2 Session Workspace
S3 View Local State
S4 Domain State
S5 Ephemeral UI

4. Layer Definitions
4.1 S1 Persistent Layout

사용자 UI 레이아웃

예: panel positions, sidebar state, editor tabs

특징: persisted (디스크 저장), user-specific

4.2 S2 Session Workspace

IDE session 상태

예: active repository, open files, selected surface

특징: session scoped (IDE 실행 동안 유지)

4.3 S3 View Local State

Surface 내부 UI 상태

예: graph zoom, panel filters, table sorting

특징: surface-local

4.4 S4 Domain State

DevOS 핵심 상태

예: agent runs, review bundles, knowledge graph, timeline events, orchestrator runs

특징: event derived (이벤트 기반 생성), immutable snapshot

4.5 S5 Ephemeral UI

일시적 UI 상태

예: hover, tooltip, drag, loading

5. Domain State Ownership

각 surface는 특정 domain state를 소유한다.

Surface State
Editor editor session
Agent Workspace agent runs (AgentUnit — RFC-008 canonical)
Review Evidence review bundles
Temporal Replay event timeline

Orchestrator orchestration runs

8. Event Model

DevOS는 event-driven state architecture다.

Canonical 이벤트 구조는 이 문서(RFC-010-V2)에서 정의하는 workspace-aware DevOSEvent를 사용한다.

interface DevOSEvent {
  id: string
  timestamp: number
  workspaceId: string
  sessionId?: string
  repoId?: string
  agentId?: string
  runtimeId?: string
  domain: "editor" | "analysis" | "agent" | "review" | "timeline" | "graph" | "workspace" | "policy"
  type: string
  payload: unknown
}

13. Synchronization Strategy

방식 설명

14. Conflict Rules

Rule 1: Domain State는 immutable
Rule 2: Surface는 직접 state mutation 금지
Rule 3: 모든 mutation은 event로 표현

15. Performance Strategy

기술 설명
state sharding state 분할
event batching 이벤트 묶기
projection caching view model 캐시

16. Acceptance Criteria

구조:
- 5-layer state 모델 유지
- surface state isolation

기능:
- cross-surface navigation 가능
- event 기반 상태 업데이트

확장:
- 새 surface 추가 가능

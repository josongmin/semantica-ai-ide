1. Summary

이 문서는 현재 semantica-code-agent-plugin 모노레포를 ide-v2 아키텍처로 전환하기 위한 구조를 정의한다.

핵심 원칙:
- 현재 잘 동작하는 것(FSD, Jotai, Tailwind, PlatformAdapter)은 깨지 않는다
- 새로운 것(Integration Kernel, Surface zones, Transport Bridge)은 경계가 명확한 패키지/레이어로 추가한다
- VSCode webview와 Tauri desktop은 동일 src/를 공유한다

3. 문제점

| 문제 | 설명 |
|------|------|
| Transport 결합 | `postMessage`가 vscodeApi에 직접 의존. Tauri에서는 WsTransport인데 추상화 없음 |
| Panel 하드코딩 | panelAtoms.ts에 37개 atom이 flat하게 나열. zone 개념 없음 |
| Surface 부재 | 현재는 chat 중심 단일 페이지. ide-v2의 6개 surface 수용 구조 없음 |
| Kernel 부재 | Integration Kernel이 패키지로 존재하지 않음. query/event/policy 계층 없음 |
| Editor 부재 | Monaco 기반 Editor Surface 자체가 없음 |

4. 목표 구조

4-0. SOTA 레포 설계 원칙

| 원칙 | 설명 |
|------|------|
| Strict DAG | 패키지 의존은 단방향 DAG. 순환 참조 금지. **Turborepo `boundaries` + tags**로 강제 |
| Internal Packages | dev 시 패키지 빌드 없이 **TS 소스 직접 import**. 프로덕션만 tsup 빌드 |
| Apps = Thin Shell | apps/는 platform glue만. 로직은 packages/ 또는 src/ |
| Root = Webview | root package.json이 곧 webview app. 별도 apps/webview 불필요 (VSCode/Tauri 둘 다 동일 dist/ 소비) |
| Package = 독립 빌드/테스트 | 각 package는 `pnpm --filter @semantica/X test` 가능 |
| Subpath Exports | 패키지 내부 구조를 `exports`로 숨김. 소비자는 공개 API만 접근 |
| FSD in src/ | src/ 내부는 Feature-Sliced Design: surfaces > widgets > features > entities > shared |
| UI는 추출 안함 | design system은 src/shared/ui에 유지. 이유: VSCode/Tauri 둘 다 동일 빌드 소비, Tailwind 빌드 컨텍스트 단일화 |
| Schema-First | protocol 타입은 Zod schema가 SSOT. 런타임 검증 + 타입 추론 동시 제공 |
| Affected-Only CI | `turbo run test --affected`로 변경된 패키지만 CI 실행. Remote caching으로 중복 빌드 제거 |

4-1. 패키지 의존 DAG

```
L0  @semantica/protocol          순수 타입 + zod 스키마. 의존 없음
        ↑
L1  @semantica/kernel            protocol만 의존. UI/플랫폼 의존 없음
        ↑
L1  @semantica/core              protocol만 의존. WsTransport 등 런타임 유틸
        ↑
L2  @semantica/extension-host    kernel + core 의존. VSCode API 의존
L2  @semantica/agent-runtime     protocol + core 의존. Node 런타임
        ↑
L3  apps/desktop                 kernel + core 의존. Tauri API 의존
L3  apps/agentd                  protocol + agent-runtime 의존
L3  root (src/)                  protocol + kernel 의존. React/Jotai/Tailwind
```

4-1-1. Turborepo Boundaries로 DAG 강제

eslint `no-restricted-imports`가 아닌 **Turborepo 네이티브 boundaries**를 사용한다.

패키지별 태그 (각 패키지의 `turbo.json` 또는 root `turbo.json`):
```jsonc
// turbo.json (root)
{
  "boundaries": {
    "tags": {
      "l0-protocol": {
        "packages": ["@semantica/protocol"],
        "dependencies": {
          "allow": []               // 어디에도 의존 금지
        }
      },
      "l1-infra": {
        "packages": ["@semantica/kernel", "@semantica/core"],
        "dependencies": {
          "allow": ["l0-protocol"]  // L0만 의존 가능
        }
      },
      "l2-host": {
        "packages": ["@semantica/extension-host", "@semantica/agent-runtime"],
        "dependencies": {
          "allow": ["l0-protocol", "l1-infra"]
        }
      },
      "l3-app": {
        "packages": ["@semantica/desktop", "@semantica/agentd", "semantica-code-agent-plugin"],
        "dependencies": {
          "allow": ["l0-protocol", "l1-infra", "l2-host"]
        }
      },
      "l3-webview": {
        "packages": ["semantica-code-agent-plugin"],
        "dependencies": {
          "deny": ["@semantica/extension-host", "@semantica/agent-runtime"]
          // webview는 L2 직접 참조 금지 — kernel을 통해서만 소통
        }
      }
    }
  }
}
```

CI에서 검증:
```bash
turbo boundaries    # 전체 검증 — CI에서 필수
turbo boundaries --affected  # PR에서 변경된 패키지만 검증
```

transitive violation도 감지: A→B→C에서 C가 deny 태그면 A도 위반.

4-3. Internal Packages + Subpath Exports

**Internal Packages 패턴**: dev 시 TS 소스를 직접 import하고, 프로덕션 빌드 시에만 dist/를 사용한다.
이렇게 하면 패키지 수정 → 즉시 반영. 별도 watch/rebuild 불필요.

```jsonc
// packages/protocol/package.json
{
  "name": "@semantica/protocol",
  "type": "module",
  "exports": {
    ".":            { "types": "./src/index.ts",          "import": "./dist/index.js" },
    "./models":     { "types": "./src/models/index.ts",   "import": "./dist/models/index.js" },
    "./viewmodels": { "types": "./src/viewmodels/index.ts", "import": "./dist/viewmodels/index.js" },
    "./events":     { "types": "./src/events.ts",         "import": "./dist/events.js" },
    "./commands":   { "types": "./src/commands.ts",       "import": "./dist/commands.js" }
  },
  "scripts": {
    "build": "tsup",
    "dev": "tsup --watch",
    "test": "vitest run",
    "typecheck": "tsc --noEmit"
  },
  "devDependencies": {
    "tsup": "^8.0.0",
    "vitest": "^4.0.0"
  }
}

// packages/kernel/package.json
{
  "name": "@semantica/kernel",
  "type": "module",
  "exports": {
    ".":           { "types": "./src/index.ts",           "import": "./dist/index.js" },
    "./transport": { "types": "./src/transport/types.ts",  "import": "./dist/transport/types.js" },
    "./query":     { "types": "./src/query/types.ts",      "import": "./dist/query/types.js" },
    "./event":     { "types": "./src/event/types.ts",      "import": "./dist/event/types.js" },
    "./lsp":       { "types": "./src/lsp/types.ts",        "import": "./dist/lsp/types.js" }
  },
  "dependencies": {
    "@semantica/protocol": "workspace:*"
  },
  "scripts": {
    "build": "tsup",
    "dev": "tsup --watch",
    "test": "vitest run",
    "typecheck": "tsc --noEmit"
  }
}
```

핵심: `"types"` 필드가 `./src/*.ts`를 직접 가리킨다.
- Vite/esbuild가 dev 시 TS 소스를 직접 트랜스파일 → **빌드 0초**
- `tsc --noEmit`은 소스 레벨에서 타입 체크

5. 핵심 설계 결정

5-1. FSD 구조 확장: pages → surfaces

현재 FSD의 `pages/`는 chat, review, arena 등 6개.
ide-v2는 6개 surface가 필요하다.

결정: `surfaces/` 디렉토리를 신규 추가한다.
- `pages/`는 기존 코드 호환을 위해 유지
- `surfaces/`는 RFC surface 단위로 구성
- 점진적으로 `pages/chat` → `surfaces/chat`으로 이동

이유:
- pages와 surfaces는 개념적으로 다름 (page는 라우팅 단위, surface는 IDE zone 단위)
- surface는 동시에 여러 개가 활성화됨 (page는 하나)
- 기존 pages를 깨지 않고 새 구조를 추가할 수 있음

5-2. packages/kernel — Integration Kernel 분리

Integration Kernel은 프론트 src/ 안이 아니라 packages/로 분리한다.

이유:
- kernel은 transport 추상화를 포함하므로 extension-host와 desktop 양쪽에서 사용
- 도메인 로직(query routing, job management, result normalization)이 UI와 무관
- 테스트를 UI 없이 독립 실행 가능
- agentd에서도 kernel 타입을 참조 가능

5-3. packages/protocol/models — Canonical 모델 중앙화

RFC-012에서 정의한 canonical 모델(DevOSEvent, AgentUnit, OrchestratorRun 등)은
`packages/protocol/src/models/`에 중앙 배치한다.

이유:
- frontend, extension-host, agentd, kernel 모두 동일 타입 참조
- 모델 충돌 방지 (RFC-012 Section 7 SSOT)
- import 경로가 `@semantica/protocol/models/agent` 형태로 통일

5-4. Transport Bridge — postMessage vs WebSocket 추상화

```typescript
// packages/kernel/src/transport/types.ts
interface TransportBridge {
  send(command: DevOSCommand): void
  onEvent(handler: (event: ServerEvent) => void): Unsubscribe
  getState(): TransportState
  setState(state: TransportState): void
}
```

구현체:
- `PostMessageTransport` — VSCode webview용 (acquireVsCodeApi)
- `WsTransport` — Tauri/Web용 (WebSocket → agentd)
- `DevTransport` — 개발용 (localStorage + mockBackend)

감지 로직:
```typescript
// src/shared/lib/transport/detectPlatform.ts
function detectPlatform(): "vscode" | "tauri" | "web" {
  if (typeof acquireVsCodeApi !== "undefined") return "vscode"
  if ("__TAURI_INTERNALS__" in window) return "tauri"
  return "web"
}
```

5-5-1. 패널 위치 변경 시스템

패널은 3가지 방법으로 위치를 변경할 수 있다.

1. 드래그 앤 드롭
   - 패널 탭을 잡아서 다른 zone의 탭 바로 드래그
   - 드롭 타겟 zone에 시각적 하이라이트 표시
   - 허용된 zone에만 드롭 가능 (allowedZones)
   - 드래그 중 반투명 프리뷰 표시

2. 컨텍스트 메뉴 (우클릭 / 탭 옵션)
   - "Move to Right" / "Move to Bottom" / "Move to Sidebar" / "Pop out" 메뉴
   - 현재 zone 외의 허용된 zone만 메뉴에 노출

3. 커맨드 팔레트
   - `semantica.movePanel` 명령으로 프로그래밍 방식 이동
   - `Cmd+Shift+P` → "Move Panel: Impact → Bottom"

5-5-2. Zone Layout Persistence (S1 Layer — RFC-010)

패널 배치 상태는 5-Layer State의 S1 (Persistent Layout)에 저장된다.

```typescript
interface ZoneLayoutState {
  // zone별 패널 배치
  zones: Record<ZoneId, {
    panels: string[]            // 패널 ID 순서 (탭 순서)
    activePanel?: string        // 현재 활성 탭
  }>
  // zone 사이즈
  sizes: {
    sidebarWidth: number        // px, 기본 240
    rightWidth: number          // px, 기본 360
    bottomHeight: number        // px, 기본 200
    rightTopRatio: number       // 0~1, AI:Context 비율, 기본 0.6
  }
  // zone 접힘 상태
  collapsed: {
    sidebar: boolean
    right: boolean
    bottom: boolean
  }
}
```

저장 위치:
- VSCode: `vscodeApi.setState()` → workspaceState
- Tauri: `@tauri-apps/plugin-store` → local JSON
- Web: localStorage

IDE 재시작 시 마지막 배치 복원.

8. 패키지 의존성 그래프

섹션 4-1의 DAG를 재확인한다.

```
L0   @semantica/protocol ─────────── 순수 타입, 의존 없음 (zod만)
        ↑           ↑
L1   @semantica/kernel    @semantica/core
     (protocol만)         (protocol만)
        ↑                    ↑
L2   @semantica/extension-host    @semantica/agent-runtime
     (kernel + core + vscode)     (protocol + core + node)
        ↑                              ↑
L3   src/ (webview)              apps/agentd
     (protocol + kernel)         (protocol + agent-runtime)
        ↑
L3   apps/desktop
     (protocol + kernel + core + tauri)
```

Import 규칙:
- L0 → 없음 (최하위)
- L1 → L0만
- L2 → L0 + L1
- L3 → L0 + L1 + L2 (단, src/는 extension-host 직접 참조 금지)
- 같은 레벨 간 참조 금지 (kernel ↔ core 직접 참조 없음)

이 규칙은 `turbo boundaries`로 CI에서 강제한다 (섹션 4-1-1 참조).

11-2. Guard 스크립트

```typescript
// tools/bundle-guard.js
import { readFileSync, statSync } from "fs"
import { gzipSync } from "zlib"
import { glob } from "glob"

const budgets = JSON.parse(readFileSync("tools/bundle-budget.json", "utf8")).budgets
let failed = false

for (const budget of budgets) {
  const files = glob.sync(budget.path)
  for (const file of files) {
    const raw = readFileSync(file)
    const gzipped = gzipSync(raw)
    const sizeKb = (gzipped.length / 1024).toFixed(1)
    const maxKb = parseFloat(budget.maxSize)
    const warnKb = parseFloat(budget.warning)

    if (parseFloat(sizeKb) > maxKb) {
      console.error(`❌ ${budget.name}: ${sizeKb}kb > ${maxKb}kb`)
      failed = true
    } else if (parseFloat(sizeKb) > warnKb) {
      console.warn(`⚠️  ${budget.name}: ${sizeKb}kb > ${warnKb}kb (approaching limit)`)
    } else {
      console.log(`✓  ${budget.name}: ${sizeKb}kb`)
    }
  }
}

if (failed) process.exit(1)
```

CI에서 PR마다 실행. 예산 초과 시 merge 차단.

17. 핵심 결론

이 구조의 핵심은 5가지:

1. **기존 코드를 깨지 않는다** — src/ FSD 구조, panelAtoms, widgets, composites 전부 유지
2. **새 경계를 기계적으로 강제한다** — Turborepo `boundaries` + tags로 DAG 위반 CI 차단
3. **VSCode/Tauri 차이를 한 곳에서 흡수한다** — TransportBridge + PlatformAdapter
4. **개발 속도를 극대화한다** — Internal Packages(빌드 0초) + remote caching + affected-only CI
5. **품질을 자동으로 지킨다** — bundle budget guard + changesets + 패키지별 테스트 + boundary 검증

결과적으로 ide-v2 전환은 "재작성"이 아니라 "레이어 추가"로 진행되며,
추가되는 모든 경계는 **도구가 강제**한다 (컨벤션이 아닌 enforcement).

1. Summary

이 문서는 Semantica DevOS의 모든 UI Surface를 하나의 SSOT로 고정하는 문서다.

DevOS의 UI Surface는 정확히 6개다.
Core Infrastructure 계층은 Surface가 아니다.

2. DevOS Surface Map

DevOS
├ Core Infrastructure (Surface 아님)
│   ├ Integration Kernel (RFC-001)
│   ├ Query Gateway (RFC-003)
│   ├ Event Bridge (RFC-001, RFC-010)
│   └ Policy Translator (RFC-001)
│
├ Interaction Surfaces
│   ├ Editor Surface (RFC-002)
│   └ Agent Workspace Surface (RFC-006)
│
├ Intelligence Surfaces
│   ├ Review Evidence Surface (RFC-004)
│   └ Repository Knowledge Graph Surface (RFC-007)
│
├ Temporal Surfaces
│   └ Temporal Replay Surface (RFC-005)
│
└ Orchestration Surfaces
    └ Multi-Agent Orchestrator Surface (RFC-008)

주의: 기존 RFC-001에서 언급된 Runtime Surface는 RFC-014(Runtime Abstraction)에 흡수됨.
Runtime은 독립 UI Surface가 아니라 Platform Kernel의 일부로 관리된다.

3. Surface Roles
3.1 Editor Surface (RFC-002)

역할: 코드 편집, inline analysis 표시

책임:
- code editing
- symbol navigation
- inline overlays (impact, slice, taint, proof)
- diagnostics

3.2 Agent Workspace Surface (RFC-006)

역할: agent 작업 환경

책임:
- task board
- plan DAG
- context inspector
- agent execution control

3.3 Review Evidence Surface (RFC-004)

역할: patch evidence review

책임:
- diff viewer
- impact delta
- security delta
- clone delta
- metrics delta
- proof verdict

3.4 Temporal Replay Surface (RFC-005)

역할: execution timeline

책임:
- timeline
- replay
- checkpoint
- state reconstruction

3.5 Repository Knowledge Graph Surface (RFC-007)

역할: 코드베이스 구조 탐색

책임:
- symbol graph
- call graph
- dependency graph
- architecture graph

3.6 Multi-Agent Orchestrator Surface (RFC-008)

역할: agent orchestration

책임:
- task DAG
- agent fleet
- candidate convergence
- approval workflow

4. Surface Interaction Model

Surface는 서로 직접 통신하지 않는다.
모든 interaction은 Integration Kernel을 통한다.

Surface
↓
Integration Kernel
↓
Query Gateway / Event Bridge
↓
Engine

5. Surface Navigation

Surface 간 이동 예시

Source Target Trigger
Editor Knowledge Graph symbol 클릭
Editor Review Evidence diff 요청
Review Temporal Replay evidence history
Orchestrator Agent Workspace agent 상세
Orchestrator Review Evidence candidate 비교

6. Surface State Ownership

각 surface는 특정 domain state를 소유한다.

Surface State Owner
Editor editor session, open files
Agent Workspace agent runs (AgentUnit — RFC-008 canonical)
Review Evidence review bundles
Temporal Replay event timeline
Knowledge Graph graph index
Orchestrator orchestration runs

7. Cross-Surface Data Flow

예시

Patch Review:
Orchestrator → Review Evidence → Editor

Impact Analysis:
Editor → Query Gateway → Knowledge Graph

Agent Execution:
Agent Workspace → Temporal Replay

8. Surface Lifecycle

Surface는 다음 lifecycle을 가진다.

단계 설명
activate surface 열림
load 데이터 로드
update 상태 변경
suspend 비활성
dispose 종료

9. Extension Model

새로운 surface는 다음 규칙을 따른다.

규칙 설명
Kernel 사용 직접 engine 호출 금지
ViewModel 사용 raw 데이터 금지
Event 기반 polling 금지
State ownership 명확 다른 surface와 겹치지 않음

10. Governance Rules

Rule 1: Surface는 engine을 직접 호출하지 않는다.
Rule 2: 모든 query는 Query Gateway를 통한다.
Rule 3: 모든 이벤트는 Event Bridge를 통한다.
Rule 4: Surface는 ViewModel만 사용한다.
Rule 5: Surface 간 직접 state mutation 금지.

11. Canonical Model 참조

Surface에서 사용하는 모든 canonical model은 RFC-012(Platform Constitution) 섹션 7에 정의된 owner를 따른다.

주요 참조:
- DevOSEvent → RFC-010 (workspace-aware)
- AgentUnit → RFC-008
- 5-Layer State → RFC-010

12. Acceptance Criteria

구조:
- 6개 surface 경계 명확
- kernel 중심 구조

기능:
- 6개 surface 동작
- cross-surface navigation

확장:
- 새 surface 추가 가능 (규칙 9 준수)

13. 핵심 결론

이 Constitution은 Semantica DevOS UI architecture의 Surface-level SSOT다.

이 문서를 기준으로 다음을 보장한다.

- surface 경계 안정성
- engine decoupling
- UI 확장성

상위 문서: RFC-012-V2 Platform Constitution

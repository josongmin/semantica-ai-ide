## 1. 목표

### 1.1 SOTA++ 정의

**SOTA++** = SOTA + 다음 4가지를 구조로 강제:

1. **Gate 강제**: P0 Gate 4개(gate-contract, gate-performance, gate-fixtures, gate-fixture-replay)가 CI에서 필수 통과. [REF-CONSOLIDATION](REF-CONSOLIDATION.md) 5절.
2. **Fixture 3종**: LLM streaming / file attachment / plugin API call 시나리오 golden 고정
3. **드리프트 봉쇄**: SSOT 변경 시 codegen + fixture replay로 검증
4. **용어/스키마 SSOT**: 모든 RFC가 동일 용어·동일 스키마 참조

### 1.2 해결한 모순 목록

| # | 모순 | 해결 |
|---|------|------|
| 1 | write_patch vs apply_patch | **apply_patch** (디스크 적용), **write_patch** (IR 생성) 둘 다 유지. 승인 대상은 apply_patch |
| 2 | payload_ref vs BlobRef | **BlobRef**로 통일 (blob-protocol 스키마) |
| 3 | SET_FINAL vs SET_MESSAGE_STATUS | **SET_MESSAGE_STATUS** (status=final) |
| 4 | ATTACHMENT_ADDED vs ADD_ATTACHMENT_REF | **ADD_ATTACHMENT_REF** |
| 5 | Delta 최소 세트 누락 | REMOVE_ATTACHMENT_REF, SET_ATTACHMENT_STATUS, SET_DIFF_LOADED 추가 |
| 6 | workspace 도구 목록 불일치 | 통합 목록 확정 |
| 7 | tool.llm.generate vs ModelPort | **ModelPort** ([RFC-000](000.md)). Orchestrator가 ModelPort 호출. Tool 아님 |
| 8 | Gate 경로 | `schemas/agent-ux/gates/` ([RFC-017](017.md) 2.2절에서 루트→SSOT 내부로 이동) |
| 9 | SSOT 구조 | RFC-006 2절에 확정. contracts, ir, errors, plugins, policy, gates, eval, dev 포함. Monorepo 경로: [RFC-017](017.md) 4절 |

## 3. Delta 타입 SSOT (agent-protocol.v1.json 기준)

| Delta | 용도 |
|-------|------|
| UPSERT_MESSAGE | 메시지 seed/업데이트 |
| APPEND_TEXT | 스트리밍 청크 |
| SET_MESSAGE_STATUS | draft / streaming / final / error |
| PUSH_TIMELINE | 타임라인 이벤트 |
| SET_PROGRESS | 진행률 |
| ADD_ATTACHMENT_REF | 첨부 추가 |
| REMOVE_ATTACHMENT_REF | 첨부 제거 |
| SET_ATTACHMENT_STATUS | uploading / ready / error |
| UPSERT_ARTIFACT_REF | 아티팩트 ref 인덱싱 |
| SET_DIFF_LOADED | diff lazy-load 완료 |
| NOP | no-op |

## 8. Gate 의존 관계

### P0 Gate (필수, 우선 구현)

```
gate-contract (스키마/금지 규칙)
    └── [RFC-016](016.md) 적용 전: DELTA_BATCH만 허용. 적용 후: DELTA_BATCH_BIN만 허용, DELTA_BATCH 금지
    └── large payload → BlobRef 강제
    └── streaming_policy 위반 시 실패

gate-performance ([RFC-004](004.md))
    └── INP, long task, frame, heap, postMessage, commit 상한

gate-fixtures (3종 시나리오)
    └── LLM streaming 1000 chars/sec
    └── file attachment (텍스트/이미지/대형)
    └── plugin API call (대형 payload + 요약 카드)

gate-fixture-replay
    └── golden fixture replay → 기대 delta 일치
```

### 8.1 SOTA+++ v2 Gate 13개 ([RFC-018](backend/018.md), Backend 전용 참조)

13개 모두 green이어야 SOTA+++ v2 claim 가능: gate-event-log-replayable, gate-ir-schema-zero-violation, gate-ir-semantic-guard, gate-tool-idempotency, gate-tool-dryrun-parity, gate-approval-policy-enforcement, gate-artifact-hash-stability, gate-agent-trajectory-golden, gate-recovery-trajectory, gate-ast-equivalence, gate-patch-revert-valid, gate-ir-replay-determinism, gate-step-partial-execution.

**v1 -> v2 변경**: gate-model-schema-zero-violation -> gate-ir-schema-zero-violation (이름 변경). gate-event-log-replayable, gate-ir-semantic-guard 추가. gate-provider-error-normalization은 운영 gate로 분류 (Tier 2).

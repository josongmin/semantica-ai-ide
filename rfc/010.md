## 1. 목표

- **Feature 기반 슬라이싱**: 도메인별 기능을 독립 슬라이스로 분리
- **FSD 패턴**: 레이어 의존 방향 준수 (shared → entities → features → widgets → pages → app)
- **앱 성격 반영**: Agent UX = 채팅 + 리뷰 + 컨텍스트 + 런타임이 결합된 제품

---

## 2. 앱 성격 분석

### 2.1 핵심 도메인

| 도메인 | 설명 | RFC 근거 |
|---------|------|----------|
| **Session** | 멀티 세션, 프로젝트별, 스냅샷/복구 | [RFC-000](000.md) 2.1 |
| **Message** | 채팅 메시지, 스트리밍, 역할 | [RFC-002](002.md), [RFC-003](003.md) |
| **Diff** | 패치 리뷰, 부분 적용, 충돌 해결 | [RFC-000](000.md) 2.1 |
| **Command** | 명령 실행 전 승인, dry-run | [RFC-000](000.md) 2.1 |
| **Context** | @file, @symbol, @search 등 주입 | [RFC-000](000.md) 2.1 |
| **Timeline** | 이벤트 로그, 아티팩트 | [RFC-005](005.md), [RFC-006](006.md) |
| **Approval** | 승인 게이트, 정책 | [RFC-000](000.md) 6.2 |
| **Runtime** | 오케스트레이션, 상태 머신 | [RFC-000](000.md) 1.2 |

### 2.2 레이어 분리 (3-버스)

| 레이어 | 위치 | 역할 |
|---------|------|------|
| **UX Layer** | Webview (FSD 적용) | 렌더 전용 thin client |
| **Orchestrator** | Extension Host | 상태 머신, ModelPort, 이벤트 루프 |
| **Tool Layer** | Extension Host | workspace/search/terminal/git 포트 구현 |

## 4. 의존 방향 (FSD 규칙)

```
app
  └── pages
        └── widgets
              └── features
                    └── entities
                          └── shared
```

- **shared**: entities, features, widgets, pages, app 모두 참조 가능
- **entities**: shared만 참조
- **features**: entities, shared 참조. 다른 feature 직접 참조 금지
- **widgets**: features, entities, shared 참조
- **pages**: widgets, features, entities, shared 참조
- **app**: pages, shared 참조

**processes (agent-runtime)**: Extension Host 전용. Webview는 Delta/이벤트로만 소통.

## 6. 외부 Rust 백엔드 연동 ([RFC-011](backend/011.md))

semantica-codegraph-v2 (Quanta 엔진, quanta-agent-layer)를 백엔드로 연동.

- **packages/quanta-bridge/**: Rust HTTP API 서버 (엔진 노출)
- **tools/analysis/**: analysis.*, index.* Tool 포트 (Quanta 클라이언트)
- **연동 대상**: WorksetApi, PatchApi, ApplyApi, TaintQuery, SymbolSearch
- **context-injection 확장**: @taint, @slice (Quanta 분석 결과 참조)

상세: [RFC-011](backend/011.md).

## 7. Public API (index.ts)

각 슬라이스는 `index.ts`로 Public API만 노출. 내부 구현 은닉.

```typescript
// features/diff-review/index.ts
export { DiffReviewActions, PartialApplyControl } from './ui';
export { useDiffReview } from './model';
```

## 9. 마이그레이션 순서

1. **Phase 1**: shared, entities 기반 구축
2. **Phase 2**: features/send-message, streaming, message-list 위젯
3. **Phase 3**: diff-review, command-review, approval-gate
4. **Phase 4**: context-injection, session-management, attachment
5. **Phase 5**: interaction-mode, timeline, 나머지 위젯

---

## 10. Import 규칙

- **Barrel export**: 각 슬라이스 `index.ts`로 Public API만 노출 (7절).
- **순환 참조 금지**: FSD 의존 방향 위반 시 빌드 검사로 차단.
- **절대 경로**: `@/` 또는 `~shared/`, `~entities/` 등 alias 사용 권장 (tsconfig paths).
- **계약**: `shared/api` 또는 `contracts/`에서 Delta/이벤트 타입 import. SSOT 생성물은 수동 편집 금지.

## 1. 목적 및 잠금 원칙

### 1.1 목적

Agent UX를 **VSCode 플러그인**, **IntelliJ 플러그인**, **Web 프론트** 3개 채널로 확장하되, 설계 드리프트를 구조적으로 불가능하게 만드는 잠금 세트를 정의함.

### 1.2 잠금 원칙 (불변)

| # | 원칙 | 설명 |
|---|------|------|
| 1 | **Protocol First, UI Second** | 프로토콜이 먼저 고정되고, UI는 그 위에 구축됨 |
| 2 | **Single Writer, Event Sourcing, Deterministic Replay** | 상태 변경은 단일 writer만 수행. 이벤트 로그가 SSOT. Replay로 동일 상태 재현 가능 |
| 3 | **동일 Session Event Log 소비** | 모든 채널은 동일한 Session Event Log를 소비하고 동일한 Projection 규칙을 적용함 |
| 4 | **렌더러 + 입력 라우팅만 채널별** | 플러그인/웹은 렌더러와 입력 라우팅만 다르고, 엔진/오케스트레이션/도구 호출은 동일 계약을 따름 |

---

## 2. 최상위 아키텍처 잠금

### 2.1 3-레이어 고정

| 레이어 | 구성요소 |
|--------|----------|
| **UX Layer** | VSCode / IntelliJ / Web |
| **Orchestrator Layer** | Session Actor + Phase machine + Policy/Budget |
| **Tooling Layer** | Workspace / Terminal / Git / Search / ModelPort |

### 2.2 3-버스 고정

| 버스 | 용도 |
|------|------|
| **Render Bus** | UI 전용 |
| **Event Bus** | 상태 변화 단일 진입점 |
| **IO/Tool Bus** | 모델/도구/파일/네트워크 전용 |

### 2.3 단일 SSOT

- **Session Event Log**가 유일 SSOT
- 모든 UI 상태는 **Projection 결과(파생)**로만 존재함
- **Replay**로 상태 재구성이 가능해야 함

## 3. 레포 구조 잠금 (모노레포)

### 3.1 루트 트리 (최종 Lock)

```
repo/
  apps/
    web/                          # 브라우저용 Agent UX (React). 렌더 전용 thin client
                                  # - session stream 구독 + projection 렌더
                                  # - 로컬 실행 제약이 크므로 tool은 주로 agent-runtime 경유

  extensions/
    vscode/                       # VSCode 플러그인 (TS)
                                  # - VSCode API로 Workspace/Terminal/Git 능력 제공
                                  # - UI는 webview로 렌더 + agent-runtime 세션에 attach

    intellij/                     # IntelliJ 플러그인 (Kotlin)
                                  # - IntelliJ VFS/Run/Git 능력 제공
                                  # - agent-runtime 세션 attach + tool routing

  servers/
    agent-runtime/                # Orchestration Edge (Node/TS)
                                  # - Session multiplexing (attach/detach, fanout)
                                  # - Event/Delta streaming (WS/SSE) + resume(cursor)
                                  # - Tool routing (client-local vs server vs engine)
                                  # - Blob proxy (대형 payload out-of-band)
                                  # - Engine RPC client (python 엔진 호출)
                                  # - "상태 변경 단일 진입점=Event"를 네트워크 경계에서 보장

  engine/
    python/                       # Intelligence Core (Python)
                                  # - 분석(정적분석/증분/쿼리) + 분석 기반 agent step 제공
                                  # - 외부로는 "엔진 RPC"로만 노출 (HTTP/gRPC/WS 중 택1)
                                  # - 결과는 protocol event + blob로 산출, replay 가능한 형태 유지

  packages/
    protocol/                     # SSOT: wire+semantic protocol (TS 단일 진실)
                                  # - Event/Command/ToolCall/BlobRef/Ids/Versioning
                                  # - forward-compatible decode 규칙
                                  # - 여기 바뀌면 모든 채널 코드 생성/호환 게이트가 따라감

    orchestrator/                 # Session Actor + reducer + phase machine (TS)
                                  # - 단일 writer 모델
                                  # - command -> event append -> state/projection 갱신
                                  # - deterministic replay (golden log 재생)

    projections/                  # event log -> UI view models (TS)
                                  # - MessageList/ToolPanel/FileDiff/Timeline 등
                                  # - 채널 공통 projection 우선
                                  # - 채널 특화는 별도 namespace로 확장

    tooling-contracts/            # Tool 인터페이스 SSOT (TS)
                                  # - Workspace/Terminal/Git/Search/ModelPort
                                  # - cancel/timeout/error schema 포함
                                  # - "tool 결과는 반드시 event로 환원" 규칙 포함

    adapters/                     # tooling-contracts 구현체 모음 (로직 금지, 능력 제공자)
      server/                     # agent-runtime 내부에서 사용하는 서버측 tool adapter
                                  # - sandbox exec, remote workspace, indexing 등

      engine/                     # agent-runtime -> python 엔진 호출 어댑터
                                  # - RPC client + 재시도/타임아웃 + 에러 매핑

      web/                        # web 환경 adapter (OPFS 또는 remote)
                                  # - 브라우저 제약 하에서 가능한 tool만
                                  # - 부족분은 server/engine 쪽으로 라우팅

      vscode/                     # VSCode adapter (FS/Terminal/Git)
                                  # - VSCode host API를 tool contract로 매핑

      intellij/                   # IntelliJ adapter (FS/Run/Git)
                                  # - IntelliJ API를 tool contract로 매핑

    ui-kit/                       # 공통 UI 컴포넌트 (TS/React)
                                  # - tool result viewer, timeline, diff card, json tree
                                  # - Monaco wrapper(선택), large payload viewer
                                  # - apps/web + extensions webview에서 공유

    shared/                       # 공통 유틸 (TS)
                                  # - ids, clock, logging, retry, backpressure helpers
                                  # - perf marks / metrics helpers

  docs/
    rfcs/                         # RFC 원본(설계 근거)
    schemas/                         # SSOT 문서(규칙/계약/스키마의 단일 진실)
    gates/                        # Gate 정의(테스트/검증)와 golden 시나리오 설명

  tooling/
    scripts/                      # 코드 생성, 릴리즈, 로컬 dev orchestration 스크립트
    ci/                           # CI 파이프라인(게이트 실행, 생성물 검증)

  examples/
    session-logs/                 # golden session event logs (replay-determinism 게이트 입력)
    golden/                       # e2e 시나리오 fixture (툴 결과/블롭/샘플 레포 등)

  .github/
    workflows/                    # gate-protocol-compat, gate-replay-determinism, gate-e2e-3channel 등

  package.json                    # pnpm workspace 루트(권장). TS 영역 전체 관리
  pnpm-workspace.yaml             # workspace 범위 정의
  tsconfig.base.json              # TS 공통 설정
  README.md                       # 전체 아키텍처 요약 + 개발 진입 가이드
```

### 3.2 채널별 역할 잠금

| 경로 | 역할 |
|------|------|
| `apps/web` | 브라우저용 Agent UX (React). session stream 구독 + projection 렌더. tool은 agent-runtime 경유 |
| `extensions/vscode` | VSCode API로 Workspace/Terminal/Git 제공. webview 렌더 + agent-runtime 세션 attach |
| `extensions/intellij` | IntelliJ VFS/Run/Git 제공. agent-runtime 세션 attach + tool routing |
| `servers/agent-runtime` | Orchestration Edge. Session multiplexing, Event/Delta streaming, Tool routing, Blob proxy, Engine RPC |
| `engine/python` | Intelligence Core. 분석 + agent step. 엔진 RPC로만 노출. protocol event + blob 산출 |

## 4. 디렉터리별 절대 규칙 (드리프트 방지 Lock)

| 디렉터리 | 절대 규칙 |
|----------|-----------|
| **protocol** (= packages/contracts) | 모든 이벤트/커맨드/블롭 참조 타입은 여기서만 정의. apps/extensions/servers/engine 어디에도 "자체 타입 정의" 금지 |
| **orchestrator** | Session 상태 변경 로직은 여기서만. 각 채널(apps/extensions)에서 reducer/phase 로직 복제 금지 |
| **adapters** | 로직 금지, 능력 제공만. "판단/계획/오케스트레이션"은 orchestrator/engine에서만 |
| **servers/agent-runtime** | 네트워크 경계에서 protocol/contract 준수 강제. 세션/스트림/블롭/라우팅이 핵심, 분석 자체는 engine으로 |
| **engine/python** | 분석과 agent intelligence만. UI/클라이언트별 분기 로직 금지 (그건 agent-runtime/adapters가 담당) |

## 5. 프로토콜 SSOT 잠금 (가장 중요)

### 5.1 패키지 단일화

- 모든 채널은 `packages/contracts`**만**을 의존하며, **로컬 타입 정의 금지** (RFC-020에서 protocol은 contracts 별칭. [GLOSSARY](GLOSSARY.md) 2절)
- protocol은 "wire + semantic"을 모두 포함하는 단일 SSOT임

### 5.2 핵심 타입 잠금 (고정 개념)

**식별자**

- SessionId, TurnId, MessageId, ToolCallId, ArtifactId

**Event**

- SessionEvent (append-only)
- ToolRequested / ToolProgress / ToolCompleted / ToolFailed
- AssistantDelta / AssistantMessageCommitted
- UserInputCommitted
- PhaseTransitioned
- BlobRef (대형 payload는 out-of-band)

**Projection**

- MessageListProjection
- ToolPanelProjection
- FileDiffProjection

**Versioning**

- protocol_version (semver)
- forward-compatible decoding 규칙

### 5.3 불변 규칙

- UI 상태는 **이벤트를 통해서만** 변함
- Tool 결과는 반드시 **Event로 환원**됨
- 모든 비결정적 요소는 Event에 "관측값"으로 고정되어 replay 시 동일해야 함

## 6. Orchestrator 잠금

### 6.1 Session Actor 단일 writer

- "상태 변경"은 Actor 내부 **reducer에서만** 발생함
- 외부는 **Command만** 보냄

### 6.2 Phase machine 고정

- Plan → Review → Apply (또는 [RFC-000](000.md) 4절 정의 phase)
- Phase 전이는 **Event로 기록**됨
- Phase별 허용 Tool/행동은 **Policy로 고정**됨

### 6.3 Deterministic Replay

- 이벤트 로그만 있으면 **동일 상태 재현 가능**해야 함
- replay mismatch 시 reducer/adapter를 pinpoint 가능해야 함

---

## 7. 채널별 Adapter 잠금

### 7.1 Adapter는 "능력 제공자"일 뿐, 로직 금지

- 플러그인/웹이 오케스트레이션 로직을 가지면 **드리프트 발생**
- Adapter는 **tooling-contracts만** 구현함

### 7.2 어댑터 매핑

| Adapter | Workspace | Terminal | Git |
|---------|-----------|----------|-----|
| **VSCodeAdapter** | vscode FS API | vscode terminal/task | vscode git extension API 또는 서버 |
| **IntelliJAdapter** | IntelliJ PSI/VFS | IntelliJ run configurations | IntelliJ git integration |
| **WebAdapter** | OPFS 또는 서버 workspace | 서버 기반 | 서버 기반 |

## 8. Gate 잠금 (드리프트 방지 장치)

### 8.1 최소 Gate 세트 (이 레포 구조에 딱 맞게)

| Gate | 역할 |
|------|------|
| **gate-protocol-compat** | protocol semver 호환 + 생성물 최신 여부 |
| **gate-replay-determinism** | examples/session-logs 재생 결과 동일성 |
| **gate-e2e-session** | web + vscode + intellij 동일 시나리오에서 core 이벤트 구조 비교 |
| **gate-render-performance-web** | 스트리밍/가상 스크롤/대형 blob 렌더 KPI (프레임/latency) |

### 8.2 "동일 시나리오 동일 로그" 원칙

- UI는 달라도 **핵심 이벤트 구조는 동일**해야 함
- 채널별 이벤트 편차는 "UI 전용 이벤트"로 **namespace 분리**

## 9. 최종 잠금 체크리스트 (바로 적용)

### 9.1 Repo Rule

- [ ] protocol 타입 로컬 정의 금지
- [ ] orchestrator 로직 각 채널에 복제 금지
- [ ] tooling은 contracts + adapters로만 확장

### 9.2 Architecture Rule

- [ ] 상태 변경 단일 진입점 = Event
- [ ] 단일 writer = Session Actor
- [ ] replay 가능한 로그가 곧 SSOT

### 9.3 Delivery Rule

- [ ] 새로운 기능은 "protocol 이벤트 추가 → orchestrator reducer 추가 → 각 채널 projection 반영" **순서로만** 추가

# RFC-017: Monorepo 아키텍처 및 패키지 경계 잠금

| 항목 | 값 |
|------|-----|
| 상태 | Draft |
| 작성일 | 2026-03 |
| 선행 | [RFC-000](000.md), [RFC-006](006.md), [RFC-008](008.md), [RFC-009](009.md), [RFC-010](010.md), [RFC-015](backend/015.md), [RFC-016](016.md) |
| 후속 | [RFC-018](backend/018.md) |

---

## 1. 목표

### 1.1 범위

단일 패키지 구조를 **Monorepo**로 전환하여, VSCode 익스텐션/WebApp/Dev Webview 등 다양한 배포 대상을 하나의 코드베이스에서 관리한다. 환경별 차이를 Adapter로 격리하고, SSOT/Gate/Fixture로 설계 드리프트를 물리적으로 봉쇄한다.

### 1.2 핵심 원칙

| # | 원칙 | 설명 |
|---|------|------|
| 1 | **Runtime/SSOT/Gate 불변** | VSCode용이든 WebApp용이든 Agent Runtime, SSOT, Gate는 동일하게 유지 |
| 2 | **환경 차이 = Adapter** | 환경별 차이는 `apps/*`와 `services/*`의 Adapter에서만 발생 |
| 3 | **드리프트 물리 봉쇄** | `schemas/**` + `gates/**` + `fixtures/**`로 강제 |

### 1.3 반드시 분리해야 하는 경계

| 패키지 | 성격 | 제약 |
|--------|------|------|
| `packages/agent-runtime` | 상태 머신 + 이벤트 + IR 처리 | **순수** (부작용 금지) |
| `packages/contracts` | JSON Schema/Protocol에서 생성된 타입 | **순수** (수동 편집 금지) |
| `services/*` | 실제 부작용 (파일/터미널/컨테이너/플러그인 로딩) | Port 구현체 |
| `apps/*` | UX 표면 (UI, VSCode, Web) | 배포 대상 |

## 2. Prior RFC 모순 해소

Monorepo 전환 시 기존 RFC들과의 불일치를 아래와 같이 해소한다.

### 2.1 SSOT 폴더명 변경

| 기존 (RFC-006 2절) | 본 RFC | 이유 |
|---------------------|--------|------|
| `schemas/agent-ux/contract/` | `schemas/agent-ux/contracts/` | 복수형으로 통일. 내부에 다수 프로토콜 공존 |
| `schemas/agent-ux/capabilities/` | `schemas/agent-ux/plugins/capability-catalog.v1.yaml` | 플러그인 중심으로 재배치 ([RFC-008](008.md)) |

### 2.2 Gates 위치 변경

| 기존 (RFC-004, 006) | 본 RFC | 이유 |
|----------------------|--------|------|
| 프로젝트 루트 `gates/` | `schemas/agent-ux/gates/` | SSOT에 gate 정의까지 포함해야 단일 진실 유지 |

Gate **실행 결과**는 `artifacts/gates/*.report.json`으로 분리하여 SSOT와 산출물을 구분한다.

### 2.3 코드 구조 통합 (RFC-010 → RFC-017)

| 기존 (RFC-010) | 본 RFC | 이유 |
|-----------------|--------|------|
| `packages/vscode-agent-ux/` (FSD 단일 패키지) | `apps/vscode-extension/src/webview/` + `packages/ui-kit/` | UI 컴포넌트 재사용성. Web/VSCode 공유 |
| `packages/extension-host-mock/` | `apps/webview-dev/src/mock-host/` | dev app 내부로 이동 |
| `packages/quanta-bridge/` | `services/quanta-bridge/` (또는 외부 프로세스) | 부작용 서비스로 분류 |

FSD 구조 자체는 유효하며, `apps/*/src/` 내부에서 FSD(shared/entities/features/widgets/pages/app) 의존 방향을 유지한다 ([RFC-010](010.md) 4절).

### 2.4 Runtime Layer 매핑 (RFC-015 → RFC-017)

[RFC-015](backend/015.md) 6 Layer를 `packages/agent-runtime/` 내부 구조에 매핑:

| RFC-015 Layer | packages/agent-runtime/src/ |
|---------------|---------------------------|
| Session Kernel | `state/` + `reducer/` |
| Model Runtime | (외부) `services/agent-host/src/model/` |
| IR Compiler | `orchestrator/` |
| Tool Execution Sandbox | (외부) `services/workspace-sandbox/` |
| Artifact Bus | (외부) `services/agent-host/src/sessions/` |
| Evaluation & Replay | `replay/` + `packages/gate-runner/` |

`packages/agent-runtime`은 **순수 레이어**(Session Kernel, IR Compiler, Replay)만 포함한다. 부작용 레이어(Model Runtime, Tool Sandbox, Artifact Bus)는 `services/*`에 배치하여 순수성을 보장한다.

### 2.5 상태명 정렬

[RFC-000](000.md)과 [RFC-015](backend/015.md)의 상태명 차이를 정리한다. RFC-015가 최신이므로 이를 기준으로 한다:

| RFC-000 | RFC-015 (기준) | 비고 |
|---------|---------------|------|
| ANALYZE | ANALYZING | 진행형 통일 |
| PLAN | PLANNING | |
| REVIEW_REQUIRED | AWAITING_APPROVAL | 의미 명확화 |
| APPLY | EXECUTING | 범위 확장 |
| ITERATE | (삭제) | RECOVERING으로 흡수 |
| DONE | COMPLETED | |
| - | RECOVERING | 신규 ([RFC-015](backend/015.md)) |

### 2.6 RFC-006에서 계획했던 RFC-017 내용 처리

[RFC-006](006.md) Phase Q에서 RFC-017로 계획했던 DeltaChannel/BlobChannel, windowing, blob eviction, ViewModel 내용은 [RFC-016](016.md)의 범위(Transferable, ring buffer, coalesce, blob 포맷)에 이미 흡수되었다. [RFC-018](backend/018.md)은 별도로 SOTA+++ v2 Runtime(Session Actor, Event Sourcing, EnginePort)을 다룬다.

### 4.2 코드에서 SSOT를 직접 import하지 않기

```
schemas/agent-ux/**          (원본, 수동 편집)
        |
        v  빌드 시점 codegen
packages/contracts/generated/**   (생성물, 수동 편집 금지)
        |
        v  import
packages/agent-runtime, services/*, apps/*
```

- 스키마/SSOT는 `packages/contracts`가 **빌드 시점에** 타입/검증기를 생성해 공급
- 런타임 패키지들은 `packages/contracts/generated`**만** 의존
- `schemas/**`를 직접 `import`하는 코드는 **lint 규칙으로 금지**

### 4.3 codegen 파이프라인

| 단계 | 입력 | 출력 | 도구 |
|------|------|------|------|
| 1 | `schemas/agent-ux/contracts/*.json` | TypeScript 타입 | json-schema-to-typescript |
| 2 | `schemas/agent-ux/ir/*.json` | IR 타입 + 검증기 | 동일 |
| 3 | `schemas/agent-ux/errors/*.json` | Error 타입 + catalog | 동일 |
| 4 | `schemas/agent-ux/plugins/*.json` | Plugin manifest 타입 | 동일 |

생성물 해시 일치는 `gate-codegen-drift`가 검증 ([RFC-006](006.md) 8절).

## 5. 패키지별 상세

### 5.1 packages/agent-runtime (순수)

[RFC-000](000.md) Orchestrator + [RFC-015](backend/015.md) Session Kernel/IR Compiler/Replay의 순수 부분만 포함.

```
agent-runtime/
  src/
    orchestrator/     # Analyze->Plan->Apply->Validate 루프
    events/           # AgentEvent 정의, 이벤트 로그
    reducer/          # AgentState 계산 (순수 함수)
    effects/          # Effect intent 생성 (부작용 없음)
    state/            # 상태 머신 정의 (RFC-015 Session Kernel)
    replay/           # Deterministic replay engine
    errors/           # AgentErrorV1 타입 (RFC-007)
  tests/
```

**의존**: `packages/contracts`만. `services/*`, `apps/*` 의존 금지.

### 5.2 packages/contracts (생성물)

```
contracts/
  schemas/        # schemas/** 원본 스키마 사본 (codegen 입력)
  generated/      # 생성된 TypeScript 타입, 검증기
  scripts/        # codegen 스크립트 (pnpm gen:contracts)
```

### 5.3 packages/tool-protocol (Port 인터페이스)

[RFC-000](000.md) 6절 Tool Layer의 **인터페이스만** 정의. 구현은 환경별 Adapter.

```
tool-protocol/
  src/
    ports/        # WorkspacePort, SearchPort, TerminalPort, GitPort, AnalysisPort
    policy/       # 승인 게이트 기본 규칙 (RFC-000 6.2절)
    types/        # ToolCallV1, ToolResultV1
```

### 5.4 packages/ui-kit (재사용 UI)

[RFC-010](010.md)의 `shared/ui/` + `entities/`를 Web/VSCode 공용 킷으로 승격.

```
ui-kit/
  src/
    components/       # 버튼, 인풋, 테마 (shared/ui)
    protocol/         # Delta 타입, postMessage bridge (shared/api)
    state-renderer/   # perfCollector (RFC-003), streaming engine (RFC-002)
```

### 5.5 packages/plugins-sdk

[RFC-008](008.md) Contribution API의 SDK.

```
plugins-sdk/
  src/
    manifest/         # Manifest parser/validator
    registry/         # registerTool, registerWorkflow
    negotiation/      # CapabilityQuery/Offer/Set
    permissions/      # 권한 검증
```

### 5.6 packages/gate-runner

```
gate-runner/
  src/
    gates/            # gate 실행기 (schemas/agent-ux/gates/ 읽기)
    loaders/          # YAML/JSON gate 스펙 로더
    reporters/        # artifacts/gates/*.report.json 출력
  bin/                # CLI 진입점
```

```
      tools/          # ToolPort 구현 (VSCode API 기반)
```

### 7.2 apps/web

```
web/
  src/
    app/              # FSD app/
    pages/            # FSD pages/
    widgets/          # FSD widgets/
    features/         # FSD features/
    entities/         # FSD entities/
    shared/           # FSD shared/
    transport/        # WebSocket/SSE
    stores/
  public/
```

### 7.3 apps/webview-dev ([RFC-009](009.md))

```
webview-dev/
  src/
    mock-host/        # ToolPort mock 구현 (RFC-009 extension-host-mock 흡수)
    fixture-loader/   # fixture 주입
    localbus/         # BroadcastChannel/EventEmitter transport
    app/              # UI 마운트 (packages/ui-kit 사용)
```

### 7.4 FSD 의존 방향 (RFC-010 유지)

`apps/*/src/` 내부에서 [RFC-010](010.md) 4절 규칙 유지:

```
app → pages → widgets → features → entities → shared
```

## 8. WebApp Adapter 전략

환경별 차이를 **Adapter로 고정**하여, 핵심 로직의 분기를 원천 차단한다.

### 8.1 ToolPort 구현 위치

`packages/tool-protocol/src/ports`에 **Port 인터페이스만** 둔다:

| 환경 | 구현 위치 |
|------|-----------|
| VSCode | `apps/vscode-extension/src/adapters/tools/*` |
| Web | `services/workspace-sandbox/src/*` |
| Dev | `apps/webview-dev/src/mock-host/*` |

### 8.2 Transport 구현 위치

메시지 프로토콜은 동일 (`agent-protocol.v1`). **transport만** 환경별 분기:

| 환경 | 메커니즘 | 구현 위치 |
|------|----------|-----------|
| VSCode | `postMessage` (Transferable, [RFC-016](016.md)) | `apps/vscode-extension/src/transport/*` |
| Web | WebSocket / SSE | `apps/web/src/transport/*` |
| Dev | LocalBus ([RFC-009](009.md)) | `apps/webview-dev/src/localbus/*` |

### 8.3 Adapter 등록 규칙

- 모든 Adapter는 `packages/tool-protocol`이 정의한 Port 인터페이스를 구현
- Adapter는 자신이 속한 `apps/*` 또는 `services/*` 내부에서만 존재
- `packages/*`가 특정 Adapter를 직접 참조하는 것은 **금지**

## 9. 플러그인 구조

### 9.1 플러그인 실행 = Registry + Host 분리

| 서비스 | 역할 | 관련 RFC |
|--------|------|----------|
| `services/plugin-registry/` | 배포, 서명, 매니페스트 검증, 버전 관리 | [RFC-008](008.md) |
| `services/agent-host/src/plugin-host/` | 로딩, 격리, 권한 강제, capability negotiation | [RFC-008](008.md) 5절 |

### 9.2 플러그인 소스 레이아웃

```
plugins/
  <publisher>.<name>/
    plugin.manifest.json
    src/
    dist/
    tests/
      fixtures/
```

- `plugin.manifest.json`은 `schemas/agent-ux/plugins/plugin-manifest.v1.schema.json`으로 검증 ([RFC-008](008.md) 3절)
- 빌드 산출물은 `dist/`로 고정
- 플러그인별 fixture는 `gate-fixtures`에서 자동 수집

### 9.3 플러그인 3종 세트 강제

| tool protocol | 도구 목록 + input/output schema | gate-plugin-manifest-validate |
| capability claim | 요구 권한 선언 | gate-plugin-permission |
| fixture | 최소 1개 golden fixture | gate-plugin-fixtures |

## 11. 패키지 경계 의존성 규칙

### 11.1 의존성 매트릭스

| 소비자 ↓ / 공급자 → | contracts | agent-runtime | tool-protocol | plugins-sdk | ui-kit | gate-runner | services/* | apps/* |
|---------------------|:---------:|:-------------:|:-------------:|:-----------:|:------:|:-----------:|:----------:|:------:|
| agent-runtime | O | - | X | X | X | X | **X** | **X** |
| tool-protocol | O | X | - | X | X | X | X | X |
| plugins-sdk | O | X | O | - | X | X | X | X |
| ui-kit | O | X | X | X | - | X | X | X |
| gate-runner | O | O | O | X | X | - | X | X |
| services/* | O | O | O | O | X | X | - | X |
| apps/* | O | O | O | X | O | X | O | - |

**O** = 의존 허용, **X** = 의존 금지, **-** = 자기 자신

### 11.2 핵심 제약

| # | 규칙 | 이유 |
|---|------|------|
| 1 | `packages/agent-runtime`은 `packages/contracts`**만** 의존 | 순수성 보장 |
| 2 | `packages/agent-runtime` → `services/*`, `apps/*` 의존 **금지** | 부작용 격리 |
| 3 | `services/*` → `packages/{agent-runtime, contracts, tool-protocol, plugins-sdk}` 의존 가능 | Port 구현체이므로 Port 정의 필요 |
| 4 | `apps/*`의 UI → `packages/{ui-kit, contracts}` 의존 | UI는 UI 킷과 계약만 소비 |
| 5 | `apps/*`가 런타임 직접 내장 시 → `packages/agent-runtime`**만** 의존 | 단일 경로 강제 |
| 6 | `apps/*` → `services/*` 의존은 **Web 환경만** 허용 | VSCode는 Extension Host가 역할 대체 |

### 11.3 강제 메커니즘

| 도구 | 설명 |
|------|------|
| `tsconfig.json` references | 패키지 간 명시적 참조, 순환 의존 컴파일 타임 차단 |
| ESLint `no-restricted-imports` | `schemas/**` 직접 import 금지, 역방향 의존 금지 |
| `package.json` workspace 의존성 | 허용된 의존만 명시 |
| `gate-codegen-drift` | SSOT → generated 해시 불일치 시 CI 실패 |

## 1. 목표

현재 **계층 우선(Layer-first)** FSD 구조를 **도메인 우선(Domain-first) + FSD 하위** 구조로 전환한다.

- **도메인 격리**: 도메인별 변경 영향 범위 축소
- **규모 확장**: 팀/책임 도메인 단위 분리 용이
- **번들 분리**: 도메인별 코드 스플리팅 자연스러움
- **이해 용이**: "chat 관련 코드는 어디?" → `domains/chat/` 단일 위치

## 2. 현황 분석

### 2.1 현재 구조 (계층 우선)

```
src/
├── app/
├── pages/
├── widgets/      # 137개 슬라이스
├── features/     # 146개 슬라이스
├── entities/     # 36개 슬라이스
├── shared/
└── surfaces/     # 14개 화면 (chat, editor, overview, graph, ...)
```

- `surfaces/` = 라우팅/탭 단위. FSD 계층이 아님.
- `entities`, `features`, `widgets` = 전역 평면. 도메인별 nesting 없음.
- [RFC-010](010.md) 의존 방향은 유지되나, 도메인 경계가 모호함.

### 2.2 SurfaceId 기준 도메인 목록 (14개)

| SurfaceId | 설명 | 주요 의존 |
|-----------|------|-----------|
| chat | 에이전트 채팅 | message, session, send-message, prompt-box |
| editor | 코드 에디터 | editor atoms, theme-settings |
| overview | 리포 개요 | repo-explain, ArchDiagram |
| graph | 워크스페이스 그래프 | workspace-graph, workspace-awareness |
| review | 코드 리뷰 | diff, review-comment, evidence-trace |
| replay | 타임라인 재생 | timeline-event, checkpoint |

| agents | 에이전트 플릿 | parallel-agents, background-agent |
| orchestrator | 오케스트레이션 | task DAG, approval |
| tasks | 할 일 관리 | project-todo, boomerang-tasks |

### 2.4 기존 FSD 위반 사항

코드베이스 분석 결과 발견된 의존 방향 위반. 도메인 전환과 별개로 선행 수정 권장.

| 위치 | 위반 내용 | 조치 |
|------|-----------|------|
| `surfaces/editor/useCodeMirrorTheme.ts` | `~features/theme-settings/model/` 직접 import (surfaces → features 위반) | theme atoms를 `shared/entities/` 또는 `shared/lib/`로 승격 |

### 2.5 Pages vs Surfaces (2축 네비게이션)

현재 앱은 **두 축**으로 화면을 구성한다. 도메인 매핑 시 이 구분을 반드시 반영한다.

| 축 | 역할 | 값 | 위치 |
|----|------|-----|------|
| **Surface** | IDE 센터 패널 탭 | editor, graph, overview, review, replay, tasks, ... | `SurfaceRouter`, 14개 |
| **Page** | 에이전트 패널(우측) 탭 | chat, sessions, arena, review, todos, settings | `currentPageAtom`, 6개 |

- **chat** page = 에이전트 채팅 (우측 패널 기본)
- **sessions** page = 세션 목록 (우측 패널)
- **arena** page = Arena/debate 모드 (우측 패널)
- **review** page = 리뷰 UI (우측 패널)
- **todos** page = Todo 보드 (우측 패널)
- **settings** page = 설정 (우측 패널 또는 모달)

**도메인 배치 (결정)**: page 전용 화면은 별도 도메인이 아닌 **기존 도메인 하위 page**로 흡수한다. 1~2개 파일짜리 빈약한 도메인 생성을 방지하고 도메인 수를 14개로 유지.

| page 전용 | 흡수 대상 | 경로 |
|-----------|-----------|------|
| arena | chat | `domains/chat/pages/arena/` |
| session-list | chat | `domains/chat/pages/sessions/` |
| todo-board | tasks | `domains/tasks/pages/todo-board/` |

```
└── index.ts            # registerSurface + barrel
```

### 3.3 의존 방향

```
app
  ├── shared/bootstrap (크로스커팅 훅)
  └── domains/<domain>/pages
        └── domains/<domain>/widgets
              └── domains/<domain>/features
                    └── domains/<domain>/entities
                          └── shared (ui, lib, protocol, entities)
```

> `shared/bootstrap`은 `shared` (entities, ui, lib, protocol)만 참조 가능. 도메인 코드는 `shared/bootstrap`을 직접 import하지 않으며, `app/bootstrapFeatures.ts`가 유일한 진입점.

**추가 규칙**:
- **도메인 간**: `domains/A` → `domains/B` 직접 import **금지**.
- **공통 필요 시**: `shared/entities` 또는 `shared/bootstrap`으로 승격.
- **surfaces 제거**: `domains/<id>/index.ts`에서 `registerSurface` 호출. `surfaces/` 폴더는 `domains/`로 흡수.

## 4. shared 확장: entities, bootstrap, widgets

### 4.1 shared/entities vs domains/*/entities

| 구분 | shared/entities | domains/X/entities |
|------|-----------------|--------------------|
| **위치** | `src/shared/entities/` | `src/domains/<domain>/entities/` |
| **용도** | 2개 이상 도메인에서 사용 | 해당 도메인에서만 사용 |
| **예시** | message, session, diff, tool-call | prompt-draft (chat), editor-tabs (editor) |
| **import** | `~shared/entities/message` | `~domains/chat/entities/prompt-draft` (상대 또는 alias) |

### 4.2 shared/bootstrap (크로스커팅 훅)

**bootstrapFeatures.ts**에서 전역 등록되는 feature 훅은 도메인에 묶기 어려움 → `shared/bootstrap/` 배치.

> **명칭**: `shared/features/` 대신 `shared/bootstrap/`을 사용한다. FSD 원본 계층에서 `shared`는 entities 이하(ui, lib, protocol)이므로, `shared/features/`는 계층 의미가 충돌한다. `bootstrap`이라는 역할 기반 이름으로 혼동을 방지한다.

| feature | 용도 | bootstrap 우선순위 |
|---------|------|---------------------|
| theme-settings | 테마 적용 | 80 |
| session-lifecycle | 세션 복구 | 90 |
| scope-guard | 스코프 가드 | -210 |
| approval-gate | 승인 어댑터 | -200 |
| session-shortcuts | 단축키 | 0 |
| send-message (hydrate) | 전송 어댑터 | -200 |
| diff-review (hydrate) | diff 어댑터 | -220 |
| slash-command (hydrate) | 슬래시 커맨드 | -230 |
| keyboard-navigation | 키보드 네비 | -240 |
| background-agent, terminal-bridge, workspace-graph, resource-monitor, intent-tracking, semantic-diff, transactional-edit | 각 도메인 sync | 0 |

→ `app/bootstrapFeatures.ts`는 `shared/bootstrap/`에서 import. 도메인 특화 훅(예: useStreamingCommit)은 해당 도메인으로.

### 4.3 shared/widgets (크로스 도메인 위젯)

에이전트 패널 상단/공통에 사용되는 위젯 → `shared/widgets/` 또는 `app/` 직속.

| 위젯 | 사용처 | 비고 |
|------|--------|------|
| feature-bar | ChatSubheader (모든 agent page) | 여러 entity/feature 의존 |
| session-switcher | App 레이아웃 | - |
| session-tab-bar | App 레이아웃 | - |
| turn-toc | App 레이아웃 | - |
| keyboard-shortcuts | App 레이아웃 | - |
| settings-menu | feature-bar | - |

배치 옵션: (A) `shared/widgets/` (B) `app/widgets/` (앱 전용이면).

## 6. 마이그레이션 전략

### 6.1 원칙

1. **점진적 이전**: 한 번에 전환 금지. 도메인 단위로 순차 이전.
2. **호환 유지**: 이전 중에는 기존 `entities/`, `features/`, `widgets/`와 새 `domains/` **병행**. import path alias로 점진 전환.
3. **공통 선행**: `shared/entities` 먼저 구축 후, 도메인별 이전.
4. **테스트 유지**: 각 단계별 CI green 유지.

### 6.2 Phase 0: 준비 (1–2일)

- [ ] `tsconfig` paths **및 `vite.config`**: `~shared/`, `~domains/chat/` 등 alias 추가 (양쪽 동기화 필수)
- [ ] `shared/entities/`, `shared/bootstrap/` 디렉터리 생성
- [ ] **alias 리매핑 전략 적용**: 기존 `~entities/*` alias를 `src/shared/entities/`로 리매핑하면 import 문 변경 없이 물리 위치만 이동 가능. Phase 1 작업량을 대폭 줄임
- [ ] eslint/import 규칙: `domains/A` → `domains/B` 금지 룰 추가 (선택)
- [ ] **code vs editor 통합 조사**: `code` surface의 실제 사용 범위를 분석하고 `domains/editor/` 통합 여부를 Phase 2 진입 전에 결정
- [ ] **surfaceRegistry.ts, SurfaceRouter.tsx 이동 계획**: `surfaces/` 루트의 라우팅 인프라를 `app/`으로 이동
- [ ] **explorer, search, symbols 등 7개 self-registering view의 배치 결정**: sidebar view이므로 `shared/views/` 또는 `app/views/` 배치 검토
- [ ] `bootstrapFeatures.ts` import 경로를 `~shared/bootstrap/`로 변경할 계획 수립

### 6.3 Phase 1: shared/entities 이전 (1–3일)

> **단축 전략**: Phase 0에서 `~entities/*` alias를 `src/shared/entities/`로 리매핑했다면, 물리 파일 이동만으로 완료. 기존 `~entities/message` import는 자동으로 새 위치를 가리킴.

- [ ] `message`, `session`, `diff`, `timeline-event`, `tool-call`, `turn-pipeline` → `shared/entities/`
- [ ] `project-todo`, `agent-instance`, `git-history`, `arena`, `transaction`, `completion-settings`, `mcp`, `mcp-app` → `shared/entities/`
- [ ] 기존 `entities/<name>/`에서 re-export 또는 deprecated 경로 유지 (임시, alias 리매핑 시 불필요)
- [ ] 도메인 전용 entities(`review-comment`, `intent-timeline`, `compaction-history` 등)는 이 단계에서 이동하지 않음 → Phase 2~3에서 해당 도메인으로 이전

### 6.4 Phase 2: 파일럿 도메인 (chat) (5–7일)

- [ ] `domains/chat/` 생성, FSD 하위 구조 (entities, features, widgets, pages) 생성
- [ ] chat 관련 features, widgets를 `domains/chat/`로 이전
- [ ] `surfaces/chat` → `domains/chat/index.ts`에서 `registerSurface` 호출
- [ ] `ChatPage`를 `domains/chat/pages/`로 이동
- [ ] **pages/ 흡수**: `pages/chat/` → `domains/chat/pages/`, `pages/arena/` → `domains/chat/pages/arena/`, `pages/session-list/` → `domains/chat/pages/sessions/`
- [ ] **bootstrapFeatures.ts 교체**: `import '~surfaces/chat'` → `import '~domains/chat'` (한 줄씩 점진 교체)
- [ ] 기존 import 경로를 새 경로로 교체

### 6.5 Phase 3: 나머지 도메인 순차 이전 (도메인당 2–4일)

권장 순서:

1. **overview** (의존 적음)
2. **editor** (editor 전용 atoms/컴포넌트)
3. **review** (diff, evidence-trace) — `pages/review/` → `domains/review/pages/` 포함
4. **graph**
5. **replay**, **agent**, **agents**
6. **orchestrator**, **tasks** — `pages/todo-board/` → `domains/tasks/pages/todo-board/` 포함
7. **reasoning**, **code**, **settings** — `pages/settings/` → `domains/settings/pages/` 포함

> **참고**: 각 도메인 이전 시 해당 도메인의 `surfaces/<id>/`, `features/`, `widgets/`, `entities/`, `pages/` 슬라이스를 모두 `domains/<id>/` 하위로 이동한다. 이전 완료 후 `bootstrapFeatures.ts`의 surface self-registration import를 `~domains/<id>`로 교체.

## 8. 미결정·경계 사항

| 항목 | 상태 | 비고 |
|------|------|------|
| **code vs editor** | **Phase 0 선결** | code surface와 editor surface 역할 중복 여부. 통합 시 `domains/editor/` 단일화. Phase 2 진입 전 결정 필수 (미결정 시 두 번 이전 위험) |
| **surfaceRegistry.ts, SurfaceRouter.tsx** | **Phase 0 선결** | `surfaces/` 루트의 라우팅 인프라. 도메인이 아니므로 `app/` 이동 |
| **explorer, search, symbols, findings, problems, output, event-log** | **Phase 0 선결** | sidebar view이므로 도메인 귀속보다 `shared/views/` 또는 `app/views/` 배치가 적절 |
| **event-dispatch** | app 유지 | `app/event-dispatch`는 entities 직접 사용. shared/entities import로 유지 |
| **app/widgets vs shared/widgets** | 배치 미결정 | SessionSwitcher 등 앱 전용이면 app/widgets 가능 |
| **FSD 위반 선행 수정** | Phase 0 권장 | `surfaces/editor/useCodeMirrorTheme.ts`의 theme-settings 직접 import (2.4절 참조) |

## 1. 아키텍처 요약

### 1.1 목표

- VSCode 상에서 Claude Code급 에이전트 UX를 **SOTA++ v1** 기준으로 설계
- 기능 확장성은 "무제한"을 전제로 하되, 설계 드리프트를 구조적으로 봉쇄하는 SSOT·계약·버전·게이트 체계를 먼저 고정

### 1.2 핵심 원리

- **"채팅 UI"가 아니라 Agent UX Runtime이 제품 본체**
- Runtime은 3층으로 분리:
  - **UX Layer**: webview + native UI
  - **Orchestrator Layer**: state machine + plan/review/apply loop + **ModelPort 호출** (모델 직접 호출 금지)
  - **Tooling Layer**: workspace/terminal/git/search 등 도구 포트
- **Orchestrator는 모델을 직접 모름**: ModelPort만 호출, 결과를 AgentEvent로 환원. 모델은 ToolCall intent(IR)만 생성, 도구 실행은 Tool Layer.

## 2. SOTA++ v1 기능 카탈로그

### 2.1 UX 표면 (사용자가 보는 것)

**Sessions**
- 멀티 세션 / 프로젝트별 세션
- 세션 스냅샷 / 복구
- 세션 타임라인 (읽기/검색/패치/명령/결과)

**Interaction Modes**
- Quick Edit, Plan Mode, Review Mode, Diagnose Mode, Refactor Mode, Generate Mode

**Context Injection**
- `@file` `@selection` `@folder` `@search` `@diagnostics` `@git` `@terminal` `@symbol` `@references` `@tests` `@docs` `@issues`
- Context budget(토큰) 시각화 및 truncation 리포트

**Diff Review**
- 파일별/헝크별 승인
- 부분 적용
- 충돌 해결 UI (3-way)

**Command Review**
- 명령 실행 전 승인
- dry-run / preview 지원

**Findings/Actions**
- TODO/Issue 생성
- 코드 주석/리뷰 코멘트 생성
- PR 생성/업데이트 (옵션)

### 2.2 에이전트 런타임 기능 (확장성 핵심)

- **Multi-step loop**: Analyze → Plan → Review → Apply → Validate → Iterate
- **IR**: Plan IR + Patch IR + Run IR (구조화)
- **Tools**: read / search / edit / run / git / test / lint / index / diagnose / trace
- **Memory**: 세션 메모리 + 워크스페이스 인덱스 (옵션)
- **Policies**: approval rules, allowed tools, scope 제한 (프로젝트/폴더)
- **Observability**: 타임라인 이벤트, artifacts, replay (옵션)

### 2.3 플러그인 생태계 확장

| 플러그인 | 용도 |
|----------|------|
| Tool | 새 도구 추가 (Jira, Notion, internal API) |
| Workflow | 새 작업 템플릿 ("대규모 리팩터", "보안 점검", "성능 튜닝") |
| Model | ModelPort Adapter (Claude/OpenAI/local). Orchestrator가 소비, Tool 아님 |
| Index | ripgrep 외 semantic index, LSP symbol graph, embeddings |

## 3. 드리프트 방지 설계 SSOT

### 3.1 SSOT 문서/스키마 세트

상세 구조는 [RFC-006](006.md) 2절. 핵심:

```
<repo_root>/
├── schemas/agent-ux/              # 원본 (수동 편집 허용)
│   ├── contracts/              # agent, tool, blob, model-protocol ([RFC-017](017.md) contract/→contracts/)
│   ├── ir/                     # plan-ir, patch-ir, run-ir, event-log, artifact-index, plugin-manifest
│   ├── errors/
│   ├── plugins/                # capabilities/ → plugins/ ([RFC-017](017.md))
│   ├── policy/
│   └── gates/                  # Gate 스펙 ([RFC-017](017.md) 2.2절: 루트 gates/ → SSOT 내부)
    ├── gates.v1.yaml
    ├── contract.v1.yaml
    └── performance.v1.yaml
```

### 3.2 변경 금지 규칙 (드리프트 봉쇄)

- UI/Orchestrator/Tools 사이에는 **오직 계약(Protocol)으로만** 통신
- 계약 스키마 변경 시 필수:
  - version bump
  - 마이그레이션(compat) 정의
  - golden fixtures 업데이트
  - gate 통과
- "임시 필드 추가" 금지 → `extensions` 네임스페이스로 확장 포인트 통과

### 3.3 Contract-first, versioning, error schema

agent-protocol, tool-protocol 공통 필수:
- `protocol_version`
- `request_id`, `trace_id`, `session_id`
- `capability_set`
- error 표준 스키마: `code`, `message`, `cause`, `retryable` ([RFC-007](007.md)에서 AgentErrorV1로 확장)

## 4. Orchestrator 상태 머신 SSOT

### 4.1 Core States (최소 불변)

| 상태 | 설명 |
|------|------|
| IDLE | 대기 |
| ANALYZE | 컨텍스트 수집/분석 |
| PLAN | 계획 수립 |
| REVIEW_REQUIRED | 사용자 리뷰 대기 |
| APPLY | 패치/명령 적용 |
| VALIDATE | 검증 |
| ITERATE | 반복 |
| DONE | 완료 |
| FAILED | 실패 |
| CANCELLED | 취소 |

### 4.2 Substates (확장 포인트)

**ANALYZE**: COLLECT_CONTEXT, SEARCH, DIAGNOSE, SUMMARIZE  
**REVIEW_REQUIRED**: REVIEW_PLAN, REVIEW_PATCH, REVIEW_COMMANDS  
**VALIDATE**: RUN_TESTS, RUN_LINT, VERIFY_BUILD, RERUN_ON_FAIL (정책 기반)

### 4.3 이벤트 기반 전환 (drift 방지 핵심)

- 오케스트레이터는 "명령형 로직"이 아니라 **이벤트 로그를 소비해 상태 전환**
- 모든 상태 전환:
  1. `AgentEvent` 입력
  2. Reducer로 `AgentState` 계산
  3. Effects는 tool 호출 "의도"만 생성, 실제 부작용은 tool layer가 수행

## 5. Plan IR / Patch IR / Run IR

### 5.1 Plan IR v1

- **목적**: 사람이 리뷰 가능한 계획
- **포함**: objectives, touched_files (path + intent), operations (edit/search/run/test), risks (옵션), acceptance (done condition)

### 5.2 Patch IR v1

- **목적**: 변경을 표준 표현으로 고정 (unified diff를 넘는 구조화)
- **최소**: file operations (create/modify/delete/rename), hunks with ranges, apply strategy (strict/lenient), conflict metadata
- **권장**: 구조화 패치가 SSOT, unified diff는 렌더링용 presentation

### 5.3 Run IR v1

- **목적**: 실행/검증을 재현 가능한 형태로 기록
- **포함**: commands (cwd, env hints, expected artifacts), approvals required, output capture policy, retry policy (옵션)

## 6. Tool Layer 포트 설계

### 6.1 Tool Categories (네임스페이스)

| 카테고리 | 도구 |
|----------|------|
| workspace.* | read_file, apply_patch, write_patch, list_files, stat_file, open_editor, diagnostics, get_blob, put_blob, put_blob_from_file, open_file_picker |
| search.* | rg_search, symbol_search, reference_search |
| terminal.* | propose_command, run_command, stream_output |
| git.* | status, diff, commit, branch, pr (옵션) |
| tests.* | discover, run, parse_results |
| index.* (옵션) | build_index, query_index |

**workspace.get_blob / put_blob**: 대형 payload는 ref로 참조, tool 포트로 fetch. postMessage에는 작은 ref만. ([RFC-001](001.md)) **apply_patch**: 승인된 패치를 디스크에 적용. **write_patch**: 패치 IR 생성. 도구 목록 SSOT: [RFC-006 4절](006.md).

### 6.2 승인 게이트 기본 규칙

| 도구 | 기본 정책 |
|------|-----------|
| read, search | 허용 (정책으로 제한 가능) |
| apply_patch | 리뷰 필수 |
| run_command | 승인 필수 |
| git commit/pr | 승인 필수 |

## 7. Gate 설계

### 7.1 Gate 종류

**P0 Gate (필수)**: gate-contract, gate-performance, gate-fixtures, gate-fixture-replay. [REF-CONSOLIDATION](REF-CONSOLIDATION.md) 5절.

| Gate | 역할 |
|------|------|
| gate-contract | protocol schema validation, backward compat, large payload must be ref |
| gate-performance | ([RFC-004](004.md)) INP/longtask/frame/heap/postMessage/commit 상한 |
| gate-fixtures | golden 3종: LLM streaming, attachment, plugin API call |
| gate-fixture-replay | fixture replay → 기대 delta 일치 |

보류 (Phase 확장 시): gate-codegen-drift, gate-reducer, gate-tools, gate-mock-tool, gate-error-catalog 등. [RFC-006](006.md) 8절 참조.

### 7.2 Capability Claim 체계

- "기능 구현 여부"를 코드에 흩뿌리지 않고 `capabilities/models.v1.yaml` SSOT로 선언 ([RFC-006](006.md) 2절)
- capability ON 조건: contract 항목 존재 + fixture 존재 + gate 통과

## 8. 코드 구조 초안 (TypeScript)

### 8.1 패키지/폴더 구조

**P0 구조**: [REPO-STRUCTURE](REPO-STRUCTURE.md). 단일 패키지 시 `src/` 루트. **상세 FSD**: [RFC-010](010.md) 3절.

```
src/
├── app/                # [FSD] 앱 진입점
├── pages/              # [FSD] chat, session-list
├── widgets/            # [FSD] message-list, message-row, diff-viewer, prompt-box
├── features/           # [FSD] send-message, streaming, diff-review, context-injection
├── entities/           # [FSD] message, session, diff, timeline-event
├── shared/             # [FSD] ui, lib, api (Delta/BlobRef)
└── contracts/          # SSOT 생성물 (수동 편집 금지)
schemas/agent-ux/          # 원본 ([RFC-006](006.md))
schemas/agent-ux/gates/    # P0 Gate 4개 ([REF-CONSOLIDATION](REF-CONSOLIDATION.md) 5절)
tests/gates/
```

processes/, tools/는 Extension Host 쪽. [RFC-010](010.md), [RFC-011](backend/011.md).

### 8.2 핵심 타입 (요지)

- **AgentEvent**: UI/Tool/Model에서 들어오는 모든 입력을 표준화
- **AgentState**: 단일 truth
- **Effect**: "tool call intent", side effect 없음
- 실제 side effect는 tool 구현이 수행 후 결과를 `AgentEvent`로 환원

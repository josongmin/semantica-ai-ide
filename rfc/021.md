## 1. 동기

### 1.1 문제

현재 Surface는 **상태 없는 뷰**로 취급됨. SurfaceRouter가 keep-alive(`display:none`)로 관리하지만:

1. **라이프사이클 부재** — Surface가 활성/비활성 전환을 감지할 수 없음. WebGL 렌더러, 폴링, 애니메이션이 비활성 상태에서도 계속 실행.
2. **프레임 설정이 하드코딩** — `isIdeMode` 조건으로 sidebar/tray 표시 여부 결정. Surface별 커스텀 불가.
3. **메모리 누수** — 한번 방문한 Surface는 영원히 마운트. 10개+ Surface가 쌓이면 메모리 압박.
4. **네비게이션 가드 없음** — 에디터에 저장 안 된 변경이 있어도 화면 전환을 막을 수 없음.
5. **Surface Instance 부재** — 동일 Surface 타입의 다중 인스턴스(editor(fileA), editor(fileB))를 구분할 수 없음.
6. **정체성 혼란** — `SurfaceId`가 타입과 인스턴스를 동시에 표현. params/guard/cache가 타입 단위로 overwrite.
7. **상태 분류 부재** — "상태 보존"의 범위가 정의되지 않음. 어떤 상태가 eviction에서 살아남아야 하는지 계약 없음.

### 1.2 SOTA 분석

| 프레임워크 | 패턴 | 차용 여부 |
|-----------|------|----------|
| **Android Fragment** | `onResume`/`onPause`/`onDestroy`, `savedInstanceState`, `setMaxLifecycle` | O — 핵심 라이프사이클 모델 |
| **iOS UIViewController** | `viewWillAppear`/`viewDidDisappear` (will/did 분리) | △ — will/did 분리는 과잉, activate/deactivate로 충분 |
| **Vue keep-alive** | `onActivated`/`onDeactivated` | O — 가장 가까운 모델 |
| **React Navigation** | `useFocusEffect`, `useIsFocused`, NavigationEntry | O — 훅 인터페이스 + entry 모델 |
| **Flutter RouteAware** | `didPushNext`/`didPopNext` | △ — 스택 기반이라 우리 모델과 불일치 |
| **Android Jetpack Compose** | `DisposableEffect` + `Lifecycle.Event` | O — 정리(cleanup) 패턴 |
| **JetBrains Platform** | `ToolWindow`, weighted dispose | O — cost-based eviction |

### 1.3 설계 원칙

| # | 원칙 | 설명 |
|---|------|------|
| 1 | **Opt-in Lifecycle** | Surface가 훅을 호출하지 않으면 아무 오버헤드 없음 |
| 2 | **Coordinator Authority** | Lifecycle 이벤트는 Navigation Coordinator가 emit. React effect/render에 의존하지 않음 |
| 3 | **Layout은 선언적** | Surface 등록 시 `layout` 필드로 프레임 허용 여부 선언. 3단계(allow/hide/force) |
| 4 | **상태 보존 우선** | keep-alive가 기본. Eviction은 cost-weighted LRU. Eviction 계약은 명시적 |
| 5 | **Instance-First** | `SurfaceInstanceId`가 1등 시민. `SurfaceTypeId`는 정의/메타 전용, active state는 항상 instance 기준 |
| 6 | **Capability ≠ Preference ≠ Effective** | 세 층을 구분. capability(product contract), preference(user state), effective(runtime resolution) |

## 2. Terminology & Ownership

### 2.1 용어 정의

| 용어 | 정의 | 소유 |
|------|------|------|
| `SurfaceTypeId` | Surface 종류 식별자. `"editor"`, `"graph"`, `"chat"` | `SurfaceDefinition` |
| `SurfaceInstanceId` | Surface 인스턴스 식별자. `"editor:abc123"`, `"graph:0"` | `NavigationEntry` |
| `NavigationEntry` | 하나의 surface instance를 나타내는 navigation 레코드 | `navigationEntriesAtom` |
| `SurfaceDefinition` | Surface 타입의 정적 메타 (layout, memoryCost, lifecycle 정책 등) | `surfaceRegistry` |
| `LifecycleEvent` | Coordinator가 emit하는 lifecycle 전환 이벤트 | `navigateAtom` (Coordinator) |
| `SurfaceLeaveDecision` | Guard의 반환 타입. allow/block/redirect | Guard 함수 |

### 2.2 소유권 분리

**SurfaceTypeId 소유** — 타입 수준 정적 메타:

| 항목 | 설명 |
|------|------|
| `layout` | 프레임 capability (allow/hide/force) |
| `pinned` | Eviction 제외 여부 |
| `memoryCost` | Eviction weight |
| `instanceMode` | singleton / multi |
| `lifecyclePolicy` | keep-alive / destroy-on-hide |
| `restorePolicy` | none / snapshot / full |
| `memoryClass` | light / medium / heavy |

**SurfaceInstanceId 소유** — 인스턴스 수준 런타임 상태:

| 항목 | 설명 |
|------|------|
| `params` | Navigation payload (immutable bootstrap input) |
| `guard` | Leave guard 함수 |
| `dirty` | 저장되지 않은 변경 여부 |
| `focus` | Input focus 소유 여부 |
| `local UI state` | 스크롤, 커서, 카메라, 필터 등 |
| `lifecycle state` | active / inactive / destroyed |

### 2.3 Active State

```typescript
// 1등 시민: instance
const activeSurfaceInstanceIdAtom = atom<SurfaceInstanceId | null>(null);

// 파생 전용: type — 편의 조회용. 직접 set 금지.
const activeSurfaceTypeIdAtom = atom<SurfaceTypeId | null>((get) => {
  const instanceId = get(activeSurfaceInstanceIdAtom);
  if (!instanceId) return null;
  const entry = get(navigationEntriesAtom).get(instanceId);
  return entry?.surfaceId ?? null;
});
```

> **불변 규칙:** `activeSurfaceTypeIdAtom`은 derived only. 직접 mutation 금지.

## 3. Surface Instance Model

### 3.1 Navigation Entry

```typescript
type SurfaceTypeId = string;     // "editor", "graph", "chat"
type SurfaceInstanceId = string; // "editor:abc123", "graph:0"

interface NavigationEntry {
  readonly instanceId: SurfaceInstanceId;
  readonly surfaceId: SurfaceTypeId;
  readonly params?: Readonly<Record<string, unknown>>; // immutable bootstrap input
  readonly createdAt: number;
}
```

### 3.2 Instance 생성 규칙

| Surface | Instance 전략 | 근거 |
|---------|---------------|------|
| `code`, `chat`, `graph` | **Singleton** — 항상 1개 | 전체 화면 Surface, 다중 불필요 |
| `editor` | **Multi** — 파일당 1개 가능 | 에디터 탭 = 인스턴스 |
| `review` | **Multi** — PR당 1개 가능 | 리뷰 세션별 분리 |
| 나머지 | **Singleton** (기본) | 대부분 단일 인스턴스로 충분 |

### 3.3 Singleton vs Multi 동작

```
Singleton: navigate("graph") → 기존 instance 재사용, params 업데이트
Multi:     navigate("editor", { file: "b.ts" }) → 새 instance 생성 또는 기존 매칭
```

매칭 규칙 (Multi):
```typescript
// 동일 surfaceId + 동일 params key → 기존 instance 재활용
function findOrCreateInstance(
  surfaceId: SurfaceTypeId,
  params?: Record<string, unknown>,
): NavigationEntry;
```

### 3.4 영향 범위

| 항목 | Before | After |
|------|--------|-------|
| active state | `activeSurfaceAtom` (type) | `activeSurfaceInstanceIdAtom` (instance) |
| active type | 직접 set | derived only |
| params 저장 | `Map<SurfaceId, params>` | `NavigationEntry.params` (entry-bound) |
| guard 등록 | `Map<SurfaceId, guard>` | `Map<SurfaceInstanceId, guard>` |
| lifecycle 이벤트 | surfaceId 기준 | instanceId 기준 |
| keep-alive | surfaceId로 관리 | instanceId로 관리 |
| eviction | surfaceId LRU | instanceId cost-weighted LRU |
| frame state | `Map<SurfaceId, state>` | `Map<SurfaceInstanceId, state>` |

## 4. Lifecycle Coordinator (핵심)

### 4.1 Authority 원칙

> **불변 규칙:** Lifecycle은 router/coordinator authority가 emit한다. Hook은 lifecycle을 소비만 한다. React render/effect는 lifecycle source of truth가 아니다.

이 원칙이 없으면 세 가지 방식이 섞이면서 드리프트 발생:
- atom derive 방식
- effect 기반 감지 방식
- router emit 방식

**이 RFC는 router emit만 허용한다.**

### 4.2 문제: React Effect 종속성

**Before (v1 설계 — 위험):**

```
atom change → React render → useEffect → lifecycle callback
```

동일 frame 내 빠른 전환 시 race condition:

```
setActiveSurface("graph")
setActiveSurface("editor")  // 같은 frame

→ activate(graph) → activate(editor) → deactivate(graph)  // 순서 꼬임
```

**After (v2+ — Coordinator-Driven):**

```
navigation intent
      │
      ▼
SurfaceLifecycleCoordinator (navigateAtom)
      │
      ├─ 1. guard check (canLeave?) → SurfaceLeaveDecision
      ├─ 2. emitDeactivate(old instance)
      ├─ 3. save frame state (old instance)
      ├─ 4. resolve/create target instance
      ├─ 5. set activeSurfaceInstanceId
      ├─ 6. restore frame state (new instance)
      ├─ 7. emitActivate(new instance)
      └─ 8. eviction check (cost-weighted)
```

### 4.3 구현: `navigateAtom`

```typescript
// app/shell/model/surfaceLifecycleAtoms.ts

type LifecycleEvent =
  | { type: "activate"; instanceId: SurfaceInstanceId }
  | { type: "deactivate"; instanceId: SurfaceInstanceId }
  | { type: "destroy"; instanceId: SurfaceInstanceId };

/** 가장 최근 lifecycle 이벤트. Coordinator가 직접 set. */
export const lifecycleEventAtom = atom<LifecycleEvent | null>(null);

/** Coordinator: 모든 navigation은 이 atom을 통해서만 발생. */
export const navigateAtom = atom(
  null,
  async (get, set, target: { surfaceId: SurfaceTypeId; params?: Record<string, unknown> }) => {
    const currentInstanceId = get(activeSurfaceInstanceIdAtom);

    // 1. Guard check → SurfaceLeaveDecision
    if (currentInstanceId) {
      const decision = await evaluateLeaveGuard(currentInstanceId);
      if (decision.kind === "block") return;
      if (decision.kind === "redirect") {
        // redirect 대상으로 재귀 navigate
        set(navigateAtom, decision.target);
        return;
      }
    }

    // 2. Deactivate old
    if (currentInstanceId) {
      set(lifecycleEventAtom, { type: "deactivate", instanceId: currentInstanceId });
    }

    // 3. Save frame state
    set(saveFrameStateAtom);

    // 4. Resolve target instance
    const entry = findOrCreateInstance(target.surfaceId, target.params);

    // 5. Set active (instance-first)
    set(activeSurfaceInstanceIdAtom, entry.instanceId);

    // 6. Restore frame state
    set(restoreFrameStateAtom, entry.instanceId);

    // 7. Activate new
    set(lifecycleEventAtom, { type: "activate", instanceId: entry.instanceId });

    // 8. Eviction check
    runEviction(get, set);
  },
);
```

### 4.4 순서 보장

```
navigate("graph")
  │
  ├─ deactivate("editor:1")     ← 반드시 먼저
  ├─ atom update
  ├─ activate("graph:0")        ← 반드시 나중
  │
  └─ React re-render            ← lifecycle과 무관
```

동일 frame 빠른 전환 시:

```
navigate("graph") → navigate("editor")

→ deactivate("editor:1")
→ activate("graph:0")
→ deactivate("graph:0")     ← coordinator가 순서 보장
→ activate("editor:1")
```

## 5. State Taxonomy

### 5.1 4분류

Surface 관련 상태를 명확히 분류. **eviction 시 무엇을 잃어도 되는가**를 결정하는 기준.

#### A. Persistent Shell State

Surface 바깥에서 살아야 하는 상태. Surface lifecycle과 무관.

| 예시 | 저장 위치 |
|------|----------|
| sidebar on/off | `sidebarVisibleAtom` |
| tray on/off | `trayVisibleAtom` |
| panel width | `sidebarWidthAtom` |
| selected nav | `activeNavCategoryAtom` |
| per-surface frame state | `perSurfaceFrameStateAtom` |

#### B. Instance Session State

Surface instance가 살아있는 동안(keep-alive 포함) 유지. Eviction 시 `restorePolicy`에 따라 snapshot 가능.

| 예시 | 소유 |
|------|------|
| editor selection / cursor | instance |
| graph camera position | instance |
| chat scroll position | instance |
| draft input text | instance |
| temporary filters | instance |
| unsaved changes (dirty flag) | instance |

#### C. Derived View State

재계산 가능한 상태. 저장 불필요.

| 예시 | 소유 |
|------|------|
| visible sections | derived |
| effective layout | derived |
| active flags | derived |
| sorted/filtered subset | derived |

#### D. Disposable Runtime State

비활성(deactivate) 시 정리해야 하는 상태. Keep-alive와 무관.

| 예시 | 정리 시점 |
|------|----------|
| polling handles | onDeactivate |
| WebGL renderer loop | onDeactivate |
| subscriptions | onDeactivate |
| temp caches | onDeactivate or onDestroy |
| animation timers | onDeactivate |

### 5.2 Eviction과 State Taxonomy 관계

```
Eviction 발생:
  ├─ A (Persistent Shell) → 영향 없음 (Surface 바깥)
  ├─ B (Instance Session) → restorePolicy에 따라:
  │     "none"     → 소실
  │     "snapshot"  → snapshotRegistry에 저장 후 소멸
  │     "full"      → 소실 안 됨 (pinned이거나 atom 외부 저장)
  ├─ C (Derived) → 재계산. 소실 무관
  └─ D (Disposable) → 이미 정리됨 (deactivate 시)
```

### 5.3 불변 규칙

> **inactive surface는 CPU/network quiet 상태여야 한다.**
> **keep-alive는 state preservation 계약이지 background execution 허용 계약이 아니다.**

## 6. Per-Surface Layout — Capability / Preference / Effective

### 6.1 3층 분리

| 층 | 이름 | 설명 | 소유 |
|----|------|------|------|
| **Capability** | `SurfaceLayout` | Surface가 허용하는가 (product contract) | `SurfaceDefinition` |
| **Preference** | User toggle state | 사용자가 원하나 (user state) | `sidebarVisibleAtom` 등 |
| **Effective** | Runtime resolution | 지금 실제 보이나 | `effectiveXxxVisibleAtom` |

> **불변 규칙:**
> - Capability는 product contract다. 런타임에 변경 불가.
> - Preference는 user state다. Surface 전환 시 저장/복원.
> - Effective는 runtime resolution 결과다. 직접 set 불가.
> - **Layout forbidden(hide) 영역은 user preference로 override 불가.**

이 분리가 없으면 focus mode, command override, modal mode, zen mode 진입 시 꼬인다.

### 6.2 SurfaceLayout 타입 — 3단계 제어

**v1 (현재 구현):** `boolean` — allow or hide

**v2+ (보강):** 3단계

```typescript
type FrameVisibility = "allow" | "hide" | "force";

interface SurfaceLayout {
  readonly sidebar?: FrameVisibility;  // default: "allow"
  readonly agent?: FrameVisibility;    // default: "allow"
  readonly tray?: FrameVisibility;     // default: "allow"
}
```

| 값 | 의미 | 예시 |
|----|------|------|
| `"allow"` | 사용자 토글 존중 | IDE 모드: 사용자가 sidebar 켜고 끌 수 있음 |
| `"hide"` | 무조건 숨김. 토글 버튼 비활성 | Graph: sidebar 필요 없음 |
| `"force"` | 무조건 표시. 사용자가 끌 수 없음 | Debug: tray(terminal) 반드시 필요 |

### 6.3 Effective Visibility Resolution

```
Capability = "force"?  ──YES──→  visible = true (preference 무시)
      │ NO
Capability = "hide"?   ──YES──→  visible = false (preference 무시)
      │ NO (= "allow")
Preference (user toggle on/off?)  ──AND──  Focus Mode (off?)
      │
      └─── effectiveXxxVisibleAtom
```

```typescript
export const effectiveSidebarVisibleAtom = atom((get) => {
  const layout = getSurfaceLayout(get(activeSurfaceTypeIdAtom));
  const vis = layout.sidebar;
  if (vis === "force") return true;
  if (vis === "hide") return false;
  return get(sidebarVisibleAtom) && !get(focusModeAtom); // "allow" → user + focus
});
```

### 6.4 Per-Surface 상태 저장/복원

```
IDE (sidebar:on) → Graph 이동
  ├─ saveFrameState()     — IDE instance 상태 저장: {sidebar:true, agent:true, tray:true}
  ├─ setActiveInstance("graph:0")
  └─ restoreFrameState("graph:0") — Graph layout capability 적용: sidebar 숨김 (hide)

Graph → IDE 복귀
  ├─ saveFrameState()     — Graph instance 상태 저장
  ├─ setActiveInstance("code:0")
  └─ restoreFrameState("code:0") — 저장된 {sidebar:true} 복원
```

### 6.5 현재 Surface별 Layout 설정

| Surface | Sidebar | Agent | Tray | 근거 |
|---------|---------|-------|------|------|
| code (IDE) | allow | allow | allow | 전통적 IDE 레이아웃 |
| editor | allow | allow | allow | 코드 편집 + 터미널 필요 |
| review | allow | allow | allow | 파일 트리 + 변경 검토 |
| chat | hide | hide | hide | 채팅 전체 화면 |

| agent | hide | allow | allow | 에이전트 보드 + 로그 |
| orchestrator | hide | allow | allow | 태스크 DAG + 에이전트 |
| reasoning | hide | allow | hide | 추론 뷰 + AI 패널 |
| tasks | hide | allow | hide | 태스크 목록 + AI |

## 7. Surface Lifecycle Hooks (P0)

### 7.1 `useSurfaceActive`

```typescript
function useSurfaceActive(instanceId: SurfaceInstanceId): boolean {
  const active = useAtomValue(activeSurfaceInstanceIdAtom);
  return active === instanceId;
}
```

### 7.2 `useSurfaceLifecycle`

```typescript
function useSurfaceLifecycle(
  instanceId: SurfaceInstanceId,
  callbacks: {
    onActivate?: () => void;
    onDeactivate?: () => void;
    onDestroy?: () => void;
  },
): void {
  const event = useAtomValue(lifecycleEventAtom);

  useEffect(() => {
    if (!event || event.instanceId !== instanceId) return;

    if (event.type === "activate") callbacks.onActivate?.();
    else if (event.type === "deactivate") callbacks.onDeactivate?.();
    else if (event.type === "destroy") callbacks.onDestroy?.();
  }, [event]);
}
```

**핵심:** lifecycle 이벤트가 React render cycle이 아니라 `navigateAtom`이 직접 emit.

### 7.3 `useSurfaceFocusEffect`

```typescript
function useSurfaceFocusEffect(
  instanceId: SurfaceInstanceId,
  effect: () => void | (() => void),
): void {
  const event = useAtomValue(lifecycleEventAtom);
  const cleanupRef = useRef<(() => void) | void>();

  useEffect(() => {
    if (!event || event.instanceId !== instanceId) return;

    if (event.type === "activate") {
      cleanupRef.current = effect();
    } else if (event.type === "deactivate" || event.type === "destroy") {
      cleanupRef.current?.();
      cleanupRef.current = undefined;
    }
  }, [event]);
}
```

## 8. Surface Eviction — Contract & Cost-Weighted LRU (P1)

### 8.1 Eviction Contract

> **핵심 질문들에 대한 답:**

| 질문 | 답 |
|------|-----|
| Eviction은 React unmount와 동일한 파괴인가? | **O.** Evict = unmount + destroy event. 컴포넌트 트리 완전 제거. |
| onDestroy 전에 state snapshot을 자동 저장하는가? | `restorePolicy: "snapshot"`인 surface만. `snapshotRegistry`에 명시적 저장. |
| snapshot 저장 실패 시 eviction 가능한가? | **O.** Eviction은 best-effort snapshot 후 강제 진행. |
| pinned는 절대 eviction 금지인가? | **O.** Hard pin. memory pressure에서도 제외. |
| budget 초과 시 memory pressure signal 없어도 evict하는가? | **O.** Navigation 직후 eviction check 실행. |
| background inactive surface는 CPU quiet 강제인가? | **O.** §5.3 불변 규칙. |

### 8.2 Cost Model

```typescript
interface SurfaceDefinition {
  // ...기존 필드
  readonly memoryCost?: number;  // default: 1
  readonly pinned?: boolean;     // default: false — hard pin, eviction 제외
}

interface EvictionPolicy {
  maxTotalCost: number;          // default: 12
  maxKeptAlive: number;          // default: 7 (hard cap)
}
```

| Surface | Memory Cost | memoryClass | 이유 |
|---------|------------|-------------|------|
| graph | 5 | heavy | WebGL context, 노드 데이터 |
| editor | 3 | medium | Monaco 에디터 인스턴스 |
| orchestrator | 2 | medium | DAG 렌더링 |
| chat | 1 | light | DOM 목록 |
| settings | 1 | light | 정적 폼 |

### 8.3 Eviction 알고리즘

```
navigate 완료 후:

1. totalCost = sum(alive instances의 memoryCost)
2. keptAlive = count(alive instances)

3. while (totalCost > maxTotalCost || keptAlive > maxKeptAlive):
     candidates = alive.filter(not pinned, not active)
     if candidates.empty → break (eviction 불가)
     candidate = candidates.sort(LRU).first
     if candidate.restorePolicy === "snapshot":
       snapshotRegistry.save(candidate.instanceId, candidate.sessionState)
     emit({ type: "destroy", instanceId: candidate.instanceId })
     unmount(candidate)
     keptAlive--; totalCost -= candidate.memoryCost
```

### 8.4 Pinned Surfaces

| Surface | Pinned | 이유 |
|---------|--------|------|
| `code` | O | IDE 핵심. 에디터 상태(탭, 커서) 손실 불가 |
| `chat` | O | 채팅 스크롤/입력 상태 보존 |

> **불변 규칙:** eviction 전 snapshot 대상 state는 explicit `snapshotRegistry`에 의해 저장된다. 암시적 저장 없음.

## 9. Navigation Guard — Leave Transaction (P2)

### 9.1 SurfaceLeaveDecision

Guard를 단순 boolean이 아닌 **leave transaction** 결과 타입으로 정의:

```typescript
type SurfaceLeaveDecision =
  | { kind: "allow" }
  | { kind: "block"; reason?: string }
  | { kind: "redirect"; target: { surfaceId: SurfaceTypeId; params?: Record<string, unknown> } };
```

이 확장으로 지원 가능:

| 시나리오 | Decision |
|---------|----------|
| 변경 없음, 자유 이동 | `{ kind: "allow" }` |
| 미저장 변경, 사용자 거부 | `{ kind: "block", reason: "unsaved changes" }` |
| 저장 후 이동 | guard에서 저장 수행 후 `{ kind: "allow" }` 반환 |
| 로그인 필요 | `{ kind: "redirect", target: { surfaceId: "settings" } }` |
| async validation 후 block | `await validate()` 후 `{ kind: "block" }` |

### 9.2 Instance-Aware Guard

```typescript
// guard는 instance 단위로 등록
const surfaceGuards = new Map<
  SurfaceInstanceId,
  () => SurfaceLeaveDecision | Promise<SurfaceLeaveDecision>
>();

function useSurfaceGuard(
  instanceId: SurfaceInstanceId,
  canDeactivate: () => SurfaceLeaveDecision | Promise<SurfaceLeaveDecision>,
): void;
```

### 9.3 Coordinator 연동

Guard check는 `navigateAtom` 내부에서 실행 (§4.3 step 1):

```typescript
async function evaluateLeaveGuard(instanceId: SurfaceInstanceId): Promise<SurfaceLeaveDecision> {
  const guard = surfaceGuards.get(instanceId);
  if (!guard) return { kind: "allow" };
  return guard();
}
```

### 9.4 사용 예시

```typescript
// EditorSurface.tsx — 인스턴스별 guard
useSurfaceGuard(instanceId, async () => {
  if (!hasUnsavedChanges) return { kind: "allow" };

  const userChoice = await showDialog("저장하지 않은 변경이 있습니다.", ["저장 후 이동", "이동", "취소"]);

  if (userChoice === "취소") return { kind: "block", reason: "user cancelled" };
  if (userChoice === "저장 후 이동") {
    await saveFile();
    return { kind: "allow" };
  }
  return { kind: "allow" }; // "이동" — 변경 버림
});
```

## 10. Surface Params — Navigation Payload (P3)

### 10.1 원칙

> **불변 규칙:**
> - params는 surface type에 귀속되지 않는다. navigation entry / surface instance에 귀속된다.
> - 동일 surface type의 재진입은 이전 params를 overwrite하지 않는다.
> - params는 immutable bootstrap input이며, mutable working state와 구분된다.

### 10.2 Entry-Bound Params

Params는 Surface 타입이 아니라 **Navigation Entry**에 바인딩:

```typescript
// NavigationEntry (§3.1)
{ instanceId: "editor:3", surfaceId: "editor", params: { file: "main.ts", line: 42 } }
```

### 10.3 인터페이스

```typescript
// 전달 — navigateAtom 경유 (유일한 경로)
set(navigateAtom, { surfaceId: "editor", params: { file: "main.ts", line: 42 } });

// 소비 — instance의 params 읽기
const params = useSurfaceParams<{ file: string; line?: number }>(instanceId);
```

### 10.4 구현

```typescript
const navigationEntriesAtom = atom<Map<SurfaceInstanceId, NavigationEntry>>(new Map());

function useSurfaceParams<T extends Record<string, unknown>>(
  instanceId: SurfaceInstanceId,
): Readonly<T> | undefined {
  const entries = useAtomValue(navigationEntriesAtom);
  return entries.get(instanceId)?.params as T | undefined;
}
```

## 11. Surface Registration Schema

### 11.1 완전한 SurfaceDefinition

```typescript
interface SurfaceDefinition {
  // === Identity ===
  readonly id: SurfaceTypeId;
  readonly label: string;
  readonly icon: string;
  readonly component: LazyExoticComponent<ComponentType>;

  // === Layout Capability ===
  readonly layout?: SurfaceLayout; // default: all "allow"

  // === Instance Policy ===
  readonly instanceMode?: "singleton" | "multi"; // default: "singleton"

  // === Lifecycle Policy ===
  readonly lifecyclePolicy?: "keep-alive" | "destroy-on-hide"; // default: "keep-alive"

  // === Eviction ===
  readonly memoryCost?: number;                       // default: 1
  readonly memoryClass?: "light" | "medium" | "heavy"; // documentation hint
  readonly pinned?: boolean;                           // default: false

  // === State Preservation ===
  readonly restorePolicy?: "none" | "snapshot" | "full"; // default: "none"

  // === Ordering ===
  readonly priority?: number;
  readonly persistence?: PersistenceScope;
}
```

### 11.2 필드 의미

| 필드 | 용도 | 왜 필요한가 |
|------|------|------------|
| `instanceMode` | singleton vs multi | 다중 인스턴스 허용 여부를 시스템이 판단 |
| `lifecyclePolicy` | keep-alive vs destroy-on-hide | 일부 surface는 비활성 시 즉시 파괴가 효율적 |
| `memoryClass` | light/medium/heavy | 메타 힌트. 디버깅/관측에 사용 |
| `restorePolicy` | eviction 시 상태 보존 수준 | snapshot 대상 여부를 시스템 규칙으로 결정 |

## 13. Invariants

> 이 섹션의 불변조건은 **구현 코드보다 상위 권한**을 가진다. 위반 시 구현이 틀린 것이지 이 조건이 틀린 것이 아니다.

### 13.1 Navigation

| # | 불변조건 |
|---|---------|
| N1 | 어느 시점에도 active surface instance는 **최대 1개**다. |
| N2 | Active instance 변경은 **`navigateAtom`(Coordinator) 경유로만** 가능하다. |
| N3 | `activeSurfaceInstanceIdAtom`에 대한 direct atom mutation은 **금지**한다. |
| N4 | `activeSurfaceTypeIdAtom`은 **derived only**. 직접 set 금지. |

### 13.2 Lifecycle

| # | 불변조건 |
|---|---------|
| L1 | Lifecycle 이벤트는 **Coordinator가 emit**한다. React effect/render에서 추론하지 않는다. |
| L2 | 동일 instance에 대해 activate/deactivate는 **교차 순서를 깨지 않는다**. (activate → deactivate → activate → ...) |
| L3 | Evicted surface는 **destroy를 정확히 1회** 받는다. |
| L4 | destroy 이후 해당 instance에 대한 lifecycle 이벤트는 **발생하지 않는다**. |

### 13.3 Visibility

| # | 불변조건 |
|---|---------|
| V1 | **Hidden surface는 input focus를 가질 수 없다.** |
| V2 | **Hidden surface는 foreground polling/WebGL rendering을 수행할 수 없다.** (CPU quiet) |
| V3 | **Layout `"hide"` 영역은 user preference로 override 불가.** |
| V4 | **Layout `"force"` 영역은 user preference로 숨길 수 없다.** |
| V5 | **Global overlays(FloatingLayer, Dialog, Toast)는 surface layout policy에 영향받지 않는다.** |

### 13.4 Guard

| # | 불변조건 |
|---|---------|
| G1 | Guard는 **leaving instance 기준**으로 평가된다. |
| G2 | Guard가 `block` 반환 시 navigation은 **완전 취소**. lifecycle 이벤트 미발생. |
| G3 | Guard는 **async 허용**. Coordinator는 guard 완료를 await한다. |

### 13.5 Eviction

| # | 불변조건 |
|---|---------|
| E1 | Pinned surface는 **절대 eviction되지 않는다**. (hard pin) |
| E2 | Active surface는 **eviction 대상이 아니다**. |
| E3 | Eviction은 **best-effort snapshot 후 강제 진행**한다. snapshot 실패가 eviction을 막지 않는다. |

### 13.6 Params

| # | 불변조건 |
|---|---------|
| P1 | Params는 **navigation entry/instance 소유**. surface type 소유가 아니다. |
| P2 | 동일 surface type 재진입은 **이전 instance의 params를 overwrite하지 않는다**. |
| P3 | Params는 **immutable bootstrap input**이다. mutable working state와 구분. |

## 14. Non-Goals & Scope Lock

### 14.1 Navigation Model Scope

> **v1은 single-active flat workbench model만 지원한다.**

### 14.2 Non-Goals (v1)

| 항목 | 상태 | 이유 |
|------|------|------|
| Nested surfaces (child surface hierarchy) | **Non-goal** | Surface는 1계층. 복잡도 대비 가치 없음 |
| Split editor groups | **Non-goal** | 에디터 분할은 surface 내부 문제, surface 시스템 아님 |
| Concurrent active surfaces (multi-active) | **Non-goal** | single-active 모델로 충분 |
| Browser-style back stack (LIFO) | **Non-goal** | Flat workbench 모델. 스택 불필요 |
| Tab reordering / drag-and-drop | **Non-goal** | Surface 레벨이 아닌 UX 레이어 |
| Multi-window workbench | **Non-goal** | 단일 window 한정 |
| Per-render inferred lifecycle authority | **Non-goal** | §4.1 위반. Coordinator만 lifecycle source |
| Arbitrary direct atom mutation for active state | **Non-goal** | §13.1 N2-N4 위반 |

### 14.3 Future Extensions (v2+에서 고려 가능)

| 항목 | 선행 조건 |
|------|----------|
| Split editor groups | Surface 내부 분할 프로토콜 정의 |
| Nested surfaces | parent-child lifecycle 연쇄 정의 |
| Multi-window workbench | window 간 surface transfer 프로토콜 |
| Persisted navigation history | NavigationEntry 직렬화 + storage adapter |
| Background task surface (headless) | lifecycle 확장 (headless state) |

> **불변 규칙:** 모든 surface 전환은 coordinator를 통해서만 일어난다. Direct atom mutation으로 active surface를 변경하면 안 된다. 이 규칙이 없으면 구현자가 편의상 `set(activeSurfaceAtom, ...)` 해버리고, 그 순간 드리프트 시작이다.

| S12 | Guard redirect chain | A→B, B guard redirect→C, 최종 C에 도착 |
| S13 | lifecyclePolicy: "destroy-on-hide" | 비활성 시 즉시 unmount + destroy, keep-alive 안 함 |
| S14 | Singleton 재진입 | navigate("graph") 두 번 → 동일 instance 재사용, activate 재발생 |

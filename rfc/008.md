# RFC-008: 플러그인 SDK 및 Contribution API

| 항목 | 값 |
|------|-----|
| 상태 | Accepted ([REVIEW](RFC-007-009-REVIEW.md)) |
| 작성일 | 2025-03 |
| 선행 | RFC-000, RFC-005, RFC-006 |
| SOTA++ | v1 |

---

## 1. 목표

### 1.1 범위

- Tool/Workflow 플러그인을 "무제한" 추가 가능하게 하되, 드리프트를 manifest + capability negotiation + gate로 봉쇄함

### 1.2 원칙

- 플러그인은 런타임에서 무작정 실행되지 않고, 반드시 **등록/검증/권한/정책**을 통과해야 함

---

## 2. 플러그인 분류

| 유형 | 설명 |
|------|------|
| **Tool Plugin** | read/search/edit/run/git/issue 등 "도구 포트" 구현체 추가 |
| **Workflow Plugin** | "작업 템플릿" 추가 (예: RefactorLarge, FixBuild, SecurityAudit) |
| **UI Contribution** (옵션) | panel/command/tree view 추가 |

---

## 3. Manifest SSOT

### 3.1 SSOT 파일

| 파일 | 용도 |
|------|------|
| `schemas/agent-ux/plugins/plugin-manifest.v1.schema.json` | Manifest JSON Schema |
| `schemas/agent-ux/plugins/plugin-registry.v1.yaml` | 등록된 플러그인 목록 SSOT |

### 3.2 Manifest 필수 필드

| 필드 | 설명 |
|------|------|
| plugin_id | reverse-domain 권장 (예: com.example.jira) |
| version | SemVer |
| entry | main 진입점 |
| contributes.tools[] | 제공 도구 목록 |
| contributes.workflows[] | 제공 워크플로우 목록 |
| capabilities.provides[] | 제공 capability |
| permissions.requested[] | 요청 권한 |
| compat.agent_protocol_range | 호환 agent-protocol 버전 범위 |
| compat.tool_protocol_range | 호환 tool-protocol 버전 범위 |

---

## 4. Contribution API (Extension Host 측)

### 4.1 원칙

등록 API는 "즉시 실행"이 아니라 **"등록 후 핸들 반환"** 구조로 고정함

### 4.2 API 시그니처 (요지)

**Tool 등록**

```
registerTool(def: ToolDefinitionV1, handler: ToolHandler): Disposable
```

**Workflow 등록**

```
registerWorkflow(def: WorkflowDefinitionV1, runner: WorkflowRunner): Disposable
```

**UI 등록 (옵션)**

```
registerPanel(def, viewProvider)
```

## 5. Capability Negotiation

### 5.1 이유

모델/오케스트레이터/플러그인 간 기능 불일치를 런타임 에러가 아니라 **협상 단계에서 컷**함

### 5.2 프로토콜

1. Agent runtime이 `CapabilityQueryV1`를 브로드캐스트
2. 플러그인은 `CapabilityOfferV1`로 응답
3. runtime이 최종 `CapabilitySetV1`를 합성하여 세션에 고정함

### 5.3 규칙

| 규칙 | 설명 |
|------|------|
| 제공 capability | SSOT 카탈로그에 정의된 것만 허용 |
| 충돌 해결 | "동일 capability 이름" 충돌 시 우선순위 규칙 SSOT로 고정 |
| 우선순위 예시 | core built-in > signed plugin > local plugin |
| 기록 | 런타임은 협상 결과를 `session.capability_set`으로 기록하고 재현 가능하게 함 |

## 6. 권한/정책

### 6.1 플러그인 요청 권한

- fs.read, fs.write, terminal.run, network.fetch, git.write 등

### 6.2 승인 게이트

플러그인 권한은 **3중 AND**:

1. manifest 요청
2. 사용자 승인
3. 정책 allowlist

### 6.3 세션 스코프 정책

- 특정 플러그인은 특정 workspace scope에서만 허용 가능
- 예: terminal.run은 기본 deny, per-session 승인

---

## 7. Gate

| Gate | 역할 |
|------|------|
| **gate-plugin-manifest-validate** | schema validation, protocol compat range 체크 |
| **gate-plugin-capability-collision** | capability 충돌이 deterministic하게 resolve됨을 검증 |
| **gate-plugin-permission** | 요청 권한이 정책과 합치될 때만 활성화됨을 검증 |
| **gate-plugin-fixtures** | fixture로 plugin 등록/협상/툴 호출 시나리오 재현 |

## 10. 보완 및 참고

### 10.1 UI Contribution 상세

- `registerPanel(def, viewProvider)`: Webview panel 확장
- `registerCommand(id, handler)`: 명령 팔레트 등록
- `registerTreeView(id, dataProvider)`: 사이드바 트리 뷰
- UI Contribution은 optional이며, Tool/Workflow 없이 단독 등록 가능

### 10.2 Disposable 패턴

- `registerTool`, `registerWorkflow` 반환 Disposable로 플러그인 비활성화 시 등록 해제
- Extension Host 종료 시 모든 Disposable dispose 호출

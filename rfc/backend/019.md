# RFC-019: Engine Execution Single Truth (수렴 다이어그램 + 실행 계약)

| 항목 | 값 |
|------|-----|
| 상태 | Draft |
| 작성일 | 2026-03 |
| 선행 | [RFC-006](../006.md), [RFC-011](011.md), [RFC-013](../013.md), [RFC-017](../017.md), [RFC-018](018.md) |

| SOTA+++ | v2 |

---

## 1. 목표

### 1.1 이 문서가 해결하는 문제

RFC-000~018은 조각이 완벽하지만 **전체 동작 그림 SSOT**가 없다.

- 실행 흐름이 어떤 순서로 어떤 구성요소를 통과하는지 한 장으로 보이지 않음
- Budget/Determinism/Adapter 경계가 어디서 강제되는지 분산되어 있음
- 각 Analyzer(Tool/Engine/Model)의 실행 계약이 카탈로그화되어 있지 않음
- IDE/Interactive 모드의 latency/streaming 계약이 명시되지 않음

### 1.2 범위

| 항목 | 설명 |
|------|------|
| **Single Truth Diagram** | Source → IR → Analyze → Plan → Execute → Validate → Gate, 한 장 |
| **Enforcement Point Map** | Budget, Determinism, Adapter 경계가 끼는 정확한 지점 |
| **Analyzer Execution Contract** | 모든 Analyzer/Tool/Engine이 선언해야 하는 실행 속성 카탈로그 |
| **IDE/Interactive Readiness** | Query latency, partial solve, streaming 계약 |
| **Convergence Index** | RFC 간 분산된 개념의 수렴 매핑 |

## 3. Enforcement Point Map

### 3.1 Budget Enforcement (리소스 제한)

| 지점 | 위치 | Budget 종류 | 초과 시 동작 | 정의 |
|------|------|-------------|-------------|------|
| B1 | Session Actor ① | session token/time budget | FAILED + 사유 | [RFC-018](018.md) 10.3 |
| B2 | EnginePort ③ | per-call token limit | fallback model or FAILED | [RFC-012](012.md) 2절 |
| B3 | EnginePort ③ | call timeout | MODEL_TIMEOUT | [RFC-018](018.md) 8.2 |
| B4 | Approval ⑤ | approval timeout | auto-reject or FAILED | [RFC-000](../000.md) 6.2 |
| B5 | Tool Sandbox ⑥ | per-tool timeout | TOOL_NONDETERMINISTIC_FAILURE | [RFC-018](018.md) 9.2 |
| B6 | Tool Sandbox ⑥ | output size limit | truncate + artifact ref | [RFC-016](../016.md) 4절 |
| B7 | Recovery ⑧ | recovery_timeout_ms | FAILED | [RFC-018](018.md) 10.3 |
| B8 | Recovery ⑧ | max_attempts / max_depth | FAILED | [RFC-018](018.md) 10.3 |

**Unified Budget Policy SSOT**: `schemas/agent-ux/policy/budget.v1.yaml`

```yaml
session:
  max_tokens: 100000
  max_duration_ms: 300000

engine:
  per_call_max_tokens: 8000
  call_timeout_ms: 30000
  schema_repair_max_retries: 2

tool:
  per_call_timeout_ms: 60000
  output_max_bytes: 10485760  # 10MB

approval:
  timeout_ms: 600000  # 10min

recovery:
  max_attempts: 3
  max_depth: 2
  timeout_ms: 60000
```

### 3.2 Determinism Enforcement (결정성 보장)

| 지점 | 위치 | 검증 내용 | Gate |
|------|------|----------|------|
| D1 | Session Actor ① | event hash chain integrity | gate-event-log-replayable |
| D2 | EnginePort ③ | IR schema + semantic validation | gate-ir-schema-zero-violation, gate-ir-semantic-guard |
| D3 | IR Validation ④ | same input → same validation result | gate-ir-replay-determinism |
| D4 | Tool Sandbox ⑥ | idempotent tool = same result | gate-tool-idempotency |
| D5 | Tool Sandbox ⑥ | dryRun parity | gate-tool-dryrun-parity |
| D6 | Artifact Bus ⑨ | sha256 hash stability | gate-artifact-hash-stability |
| D7 | Validation ⑦ | same patch → same validation | gate-ir-replay-determinism |
| D8 | Gate ⑩ | MODEL_MOCK+TOOL_MOCK replay | gate-agent-trajectory-golden |

**Determinism Policy**: 모든 구성요소는 동일한 Determinism Policy를 상속한다. 개별 예외 없음.

```yaml
# schemas/agent-ux/policy/determinism.v1.yaml
global:
  n_run_variance_tolerance: 0
  shuffle_stress_enabled: true
  replay_mode_default: MODEL_MOCK_TOOL_MOCK

per_component:
  session_actor: { deterministic: true }
  ir_validation: { deterministic: true }
  tool_sandbox:  { deterministic: per_tool_metadata }  # ToolMetadata.idempotent 참조
  artifact_bus:  { deterministic: true }
  gate_runner:   { deterministic: true }
```

### 3.3 Adapter Boundary (환경별 분기점)

| 지점 | Port 인터페이스 | 구현체 | 정의 |
|------|----------------|--------|------|
| A1 | ContextPort | VSCode: Extension Host / Web: workspace-sandbox / Dev: fixture-loader | [RFC-017](../017.md) 8절 |
| A2 | EnginePort | LLM: ModelRuntime / Quanta: quanta-bridge / Hybrid | [RFC-018](018.md) 7절, [RFC-011](011.md) |
| A3 | ToolPort | VSCode: vscode.* / Web: container / Dev: mock / Quanta: analysis.* | [RFC-017](../017.md) 8.1 |
| A4 | TransportPort | VSCode: postMessage / Web: WebSocket / Dev: LocalBus | [RFC-017](../017.md) 8.2 |

**Adapter 규칙**: Port 인터페이스는 `packages/`에 정의. 구현체는 `apps/*` 또는 `services/*`에만 존재. `packages/*`가 특정 Adapter를 참조하는 것은 금지. ([RFC-017](../017.md) 8.3절)

## 4. Analyzer Execution Contract

모든 Analyzer/Tool/Engine은 아래 속성을 선언해야 한다. 이것이 충족되면 엔진이 **"카탈로그 기반 플랫폼"**으로 승격된다.

### 4.1 Contract 스키마

```typescript
type AnalyzerExecutionContract = {
  id: string;
  category: "tool" | "engine" | "validator";

  // 결정성
  deterministic: boolean;
  idempotent: boolean;

  // 부작용
  sideEffect: "READ" | "WRITE" | "EXEC" | "NONE";
  reversible: boolean;
  dryRunSupported: boolean;

  // 승인
  approvalRequired: boolean;
  riskLevel: "LOW" | "MEDIUM" | "HIGH";

  // 리소스
  budgetDomain: "session" | "engine" | "tool";
  timeoutMs: number;
  maxOutputBytes: number;

  // 증분
  incrementalCompatibility: "FULL" | "PARTIAL" | "NONE";

  // 출력
  proofEmissionLevel: "NONE" | "EVIDENCE_REF" | "FULL_PROOF";
  outputSchema: string;  // JSON Schema $ref

  // IDE
  interactiveModeSupport: boolean;
  queryLatencyTarget: "REALTIME" | "INTERACTIVE" | "BATCH";
  // REALTIME: < 100ms, INTERACTIVE: < 2s, BATCH: unbounded

  // 증거
  evidenceRequired: boolean;
};
```

### 4.2 내장 Analyzer 카탈로그

| Analyzer | category | deterministic | sideEffect | incremental | interactive | latency | proof |
|----------|----------|:---:|:---:|:---:|:---:|---------|:---:|
| workspace.read_file | tool | Y | READ | FULL | Y | REALTIME | NONE |
| workspace.apply_patch | tool | Y | WRITE | FULL | N | INTERACTIVE | EVIDENCE_REF |
| search.rg_search | tool | Y | READ | PARTIAL | Y | REALTIME | NONE |
| terminal.run_command | tool | N | EXEC | NONE | N | BATCH | EVIDENCE_REF |
| git.commit | tool | Y | WRITE | NONE | N | INTERACTIVE | EVIDENCE_REF |
| analysis.taint_query | tool | Y | READ | FULL | Y | INTERACTIVE | FULL_PROOF |
| analysis.patch_validate | tool | Y | READ | PARTIAL | N | INTERACTIVE | FULL_PROOF |
| analysis.workset_build | tool | Y | READ | FULL | Y | BATCH | EVIDENCE_REF |
| ModelRuntime (LLM) | engine | N | NONE | NONE | N | BATCH | EVIDENCE_REF |
| Quanta (codegraph) | engine | Y | NONE | FULL | Y | INTERACTIVE | FULL_PROOF |

### 4.3 SSOT 위치

```
schemas/agent-ux/policy/analyzer-contracts.v1.yaml
```

기존 `tool-metadata.v1.yaml` ([RFC-015](015.md))을 흡수하고 확장한다. 기존 필드(sideEffect, idempotent, reversible, dryRunSupported, approvalRequired, riskLevel)는 그대로 유지하되, incrementalCompatibility, proofEmissionLevel, interactiveModeSupport, queryLatencyTarget, evidenceRequired를 추가한다.

## 5. IDE/Interactive Readiness

### 5.1 현재 갭

RFC-000~018은 **Batch 중심** 설계이다. IDE-ready 엔진이 되려면 다음이 필요:

| 항목 | 현재 상태 | 필요 |
|------|----------|------|
| Query latency contract | 미정의 | REALTIME/INTERACTIVE/BATCH 3단계 |
| Partial graph solve | 미정의 | 변경된 파일 범위만 재분석 |
| Hot path re-solve budget | 미정의 | IDE 입력 시 budget 내 재계산 |
| Interactive cache eviction | 미정의 | LRU + priority 기반 eviction |
| Query streaming protocol | 미정의 | SSE/WebSocket 기반 partial result |
| Confidence score | 미정의 | 0.0~1.0, threshold 기반 표시 |

### 5.2 Query Latency Contract

```yaml
# schemas/agent-ux/policy/interactive.v1.yaml
latency_targets:
  REALTIME:
    max_ms: 100
    use_case: "파일 읽기, 심볼 검색, 코드 네비게이션"
    degradation: "캐시 미스 시 INTERACTIVE로 승격"

  INTERACTIVE:
    max_ms: 2000
    use_case: "패치 검증, taint 쿼리, 워크셋 빌드"
    degradation: "timeout 시 partial result + confidence score"

  BATCH:
    max_ms: null  # session budget에 위임
    use_case: "LLM 호출, 전체 빌드, 대규모 리팩터"
    degradation: "session budget 초과 시 FAILED"
```

### 5.3 Partial Solve Protocol

IDE 컨텍스트에서 **전체 분석을 매번 실행하지 않는** 규칙:

| 규칙 | 설명 | 관련 |
|------|------|------|
| **ChangeSet scope** | 변경된 파일 + 영향 범위만 재분석 | [RFC-011](011.md) analysis.workset_build |
| **Invalidation** | 의존 그래프 기반 선택적 무효화 | Quanta incremental |
| **Cached result** | 이전 분석 결과가 유효하면 재사용 | artifact hash stability |
| **Partial result** | 분석 중간 결과를 confidence score와 함께 반환 | 5.4절 |

### 5.4 Confidence Score Schema

```typescript
type AnalysisResult = {
  result: unknown;          // 분석 결과
  confidence: number;       // 0.0 ~ 1.0
  completeness: "FULL" | "PARTIAL" | "CACHED";
  evidence_refs: string[];  // sha256:... artifact refs
  elapsed_ms: number;
};
```

| confidence | 의미 | UI 표시 |
|-----------|------|---------|
| 1.0 | 완전 분석 완료 | 확정 결과 |
| 0.7 ~ 0.99 | 대부분 완료, 일부 경로 미탐색 | 결과 + "일부 미확인" 배지 |
| 0.3 ~ 0.69 | 부분 결과 | 결과 + "참고용" 경고 |
| < 0.3 | 캐시 또는 추정 | "추정" 라벨, 재분석 버튼 |

### 5.5 Query Streaming Protocol

IDE/Agent 컨텍스트에서 분석 결과를 점진적으로 수신하는 프로토콜:

```typescript
type QueryStreamEvent =
  | { type: "PROGRESS"; completion: number; stage: string }
  | { type: "PARTIAL_RESULT"; result: AnalysisResult }
  | { type: "FINAL_RESULT"; result: AnalysisResult }
  | { type: "ERROR"; error: NormalizedError };
```

transport는 환경별 Adapter를 따른다 ([RFC-017](../017.md) 8.2절): VSCode=postMessage, Web=SSE, Dev=LocalBus.

## 6. Convergence Index (수렴 매핑)

### 6.1 분산된 개념 → 단일 지점

RFC 세트에서 여러 곳에 흩어져 있던 개념을 본 RFC에서 단일 지점으로 수렴한다:

| 분산된 개념 | 관련 RFC | 수렴 지점 |
|-------------|---------|-----------|
| Budget: session token limit | [RFC-018](018.md) 10.3 | 본 RFC 3.1 Unified Budget |
| Budget: model call limit | [RFC-012](012.md) 2절 | 본 RFC 3.1 B2 |
| Budget: tool timeout | [RFC-018](018.md) 9.2 | 본 RFC 3.1 B5 |
| Budget: recovery limit | [RFC-018](018.md) 10.3 | 본 RFC 3.1 B7/B8 |
| Determinism: event hash | [RFC-018](018.md) 4.2 | 본 RFC 3.2 D1 |
| Determinism: IR validation | [RFC-013](../013.md), [RFC-018](018.md) | 본 RFC 3.2 D2/D3 |
| Determinism: tool idempotent | [RFC-015](015.md) 6절 | 본 RFC 3.2 D4 |
| Determinism: artifact hash | [RFC-015](015.md) | 본 RFC 3.2 D6 |

### 6.2 Production Path 단일 경로

모든 사용자 요청은 반드시 아래 경로를 통과한다. 우회 없음:

```
USER_PROMPT
  → ① Session Actor (event append)
    → ② Context Assembly (artifact ref 수집)
      → ③ EnginePort (IR 생성)
        → ④ IR Validation (schema + semantic)
          → ⑤ Approval Gate (risk/sideEffect 기반)
            → ⑥ Tool Sandbox (preview + execute)
              → ⑦ Validation (test/lint/gate)
                → ⑨ Artifact Bus (결과 저장)
                  → Event append (COMPLETED or RECOVERING)
```

**예외 경로**: ⑧ Recovery는 ⑦ 실패 시에만 진입하며, 동일한 ③→④→⑤→⑥→⑦ 경로를 재진입한다.

## 7. Quanta 엔진 통합 강화

### 7.1 EnginePort 이중 구현

[RFC-011](011.md)의 Quanta 연동과 [RFC-018](018.md)의 EnginePort를 결합:

| EnginePort 구현 | 입력 | 출력 | 특성 |
|----------------|------|------|------|
| **LLM (ModelRuntime)** | natural language + context | PlanIR/PatchIR (비결정적) | deterministic=N, incremental=NONE |
| **Quanta (codegraph)** | structured query + workset | analysis result + proof | deterministic=Y, incremental=FULL |
| **Hybrid** | LLM이 계획, Quanta가 검증/보강 | PlanIR + evidence refs | 두 엔진 조합 |

### 7.2 Hybrid 실행 흐름

```
1. LLM EnginePort → PlanIR_v2 생성 (비결정적)
2. Quanta analysis.workset_build → 영향 범위 정밀화
3. Quanta analysis.patch_validate → GateChain 검증
4. 검증 통과 → Tool Sandbox 실행
5. 검증 실패 → Recovery (evidence ref 포함)
```

이 흐름에서 Quanta는 **"LLM 출력의 검증자"** 역할이며, 2절 다이어그램의 ③→⑦ 구간에 자연스럽게 삽입된다.

# RFC-011: 외부 Rust 엔진 연동 (Quanta + Agent Layer)

| 항목 | 값 |
|------|-----|
| 상태 | Draft |
| 작성일 | 2025-03 |
| 선행 | RFC-000, RFC-005, RFC-006, RFC-010 |
| 참조 | semantica-codegraph-v2 (Quanta 엔진, quanta-agent-layer) |
| SOTA++ | v1 |

---

## 1. 목표

- **semantica-codegraph-v2**의 Quanta 엔진 및 quanta-agent-layer를 Agent UX 백엔드로 연동
- **API 기반 연동**: 엔진은 HTTP API로 노출, Extension Host에서 API 클라이언트로 호출
- Tool Layer 확장: `index.*`, `analysis.*` 네임스페이스로 Rust 엔진 API 호출
- 계약 기반 통신으로 드리프트 방지

---

## 2. semantica-codegraph-v2 구조 요약

### 2.1 핵심 패키지

| 패키지 | 역할 | Agent UX 연동 포인트 |
|--------|------|----------------------|
| **quanta-agent-layer** | Workset, Patch, Safety Gates, AgentExecutionLoop | apply_patch 전 검증, Plan IR 연동 |
| **quanta-adapters** | Taint, Clone, CFG/DFG, PTA 분석 | search.*, index.* 확장 |
| **quanta-runtime** | 분석 런타임 (TaintQuery, Slice 등) | 컨텍스트 수집, 진단 |
| **quanta-usecase** | Usecase 레지스트리 (MCP/API/SDK) | Tool 플러그인 노출 |
| **quanta-pyo3** | Python 바인딩 | 참고: Node/TS 바인딩 없음 |

### 2.2 quanta-agent-layer API (연동 대상)

```
WorksetApi    → workset 빌드, expansion policy
PatchApi      → 패치 제안, SymbolEdit
ApplyApi      → 패치 적용 (GateChain 통과 후)
AgentExecutionLoop → Search → Workset → Patch → Gates → Approved/Rejected
```

**핵심 타입**: `AgentRequest`, `AgentResponse`, `PatchArtifact`, `SymbolEdit`, `GateChain`, `RejectReason`

### 2.3 Quanta 분석 도메인

| 도메인 | 엔진 | Agent UX 용도 |
|--------|------|---------------|
| Taint | quanta-taint-solver, codegraph-core-taint-engine | 보안 컨텍스트, @diagnostics 확장 |
| Clone | codegraph-core-clone-engine | 리팩터 모드 참조 |
| CFG/DFG | codegraph-cfg-dfg-runtime | Plan IR touched_files 검증 |
| PTA | codegraph-core-pta-engine | 호출 그래프, symbol_search |
| Spec Mining | codegraph-spec-mining-engine | (옵션) 테스트/계약 추론 |

## 3. 연동 아키텍처

### 3.1 전체 흐름

```
[Webview]  ←→  [Extension Host / Orchestrator]
                        │
                        │ Tool Call (workspace.apply_patch 등)
                        ▼
              ┌─────────────────────────────────┐
              │  Tool Layer (TypeScript)          │
              │  - workspace.*, search.*, ...    │
              │  - analysis.* (신규)             │
              └─────────────────────────────────┘
                        │
                        │ HTTP API (JSON-RPC 또는 REST)
                        ▼
              ┌─────────────────────────────────┐
              │  Quanta Engine API (Rust)       │
              │  - quanta-agent-layer           │
              │  - quanta-adapters               │
              │  - quanta-runtime                │
              └─────────────────────────────────┘
```

### 3.2 통신 방식: API 고정

**결정**: 엔진은 **HTTP API**로만 연동. Native Addon, stdio subprocess 미채택.

| 항목 | 내용 |
|------|------|
| **프로토콜** | HTTP + JSON (JSON-RPC 2.0 또는 REST) |
| **배치** | 엔진 = 별도 프로세스(서버). Extension 활성화 시 기동 또는 사용자 설정 URL |
| **이유** | 언어 독립, 디버깅 용이, MCP 호환, quanta-usecase "Surface (MCP/API/SDK)" 정렬 |

## 4. Tool 네임스페이스 확장 ([RFC-006](../006.md) 5절)

### 4.1 신규 네임스페이스: analysis.*

| 도구 | 용도 | Quanta 대응 |
|------|------|-------------|
| analysis.taint_query | Taint 분석 (source→sink) | quanta-adapters TaintQuery |
| analysis.slice | 프로그램 슬라이스 | quanta-runtime Slice |
| analysis.symbol_search | 심볼 검색 (LSP 확장) | quanta-query-layer, navigation |
| analysis.workset_build | Workset 빌드 | quanta-agent-layer WorksetApi |
| analysis.patch_validate | 패치 GateChain 검증 | quanta-agent-layer GateChain |
| analysis.patch_apply_gated | Gate 통과 후 적용 | quanta-agent-layer ApplyApiWithGateEnforcement |

### 4.2 index.* 확장 ([RFC-000](../000.md) 6.1)

| 도구 | 용도 | Quanta 대응 |
|------|------|-------------|
| index.build_index | 워크스페이스 인덱싱 | quanta-cache, quanta-adapters |
| index.query_index | 인덱스 쿼리 | quanta-query-layer |

### 4.3 workspace.apply_patch 연동

**기존**: VSCode API로 직접 파일 수정  
**확장**: apply_patch 호출 시 (정책에 따라) quanta-agent-layer GateChain 선행 검증.

```
1. Orchestrator가 apply_patch ToolCall 수신
2. (옵션) analysis.patch_validate 호출 → GateChain 결과
3. Rejected 시 AgentEvent(RejectReason) 반환, UI에 표시
4. Approved 시 workspace.apply_patch 실행 (기존 플로우)
```

## 5. 계약 (Contract) 설계

### 5.1 SSOT 확장

```
schemas/agent-ux/contracts/
├── ...
└── quanta-bridge-protocol.v1.json   # 신규 ([RFC-017](017.md) contract/→contracts/)
```

### 5.2 quanta-bridge-protocol.v1.json (초안)

```json
{
  "protocol_version": "1",
  "transport": "http_api",
  "endpoints": {
    "workset_build": { "method": "workset/build", "request": "WorksetBuildRequest", "response": "WorksetBuildResponse" },
    "patch_validate": { "method": "patch/validate", "request": "PatchValidateRequest", "response": "PatchValidateResponse" },
    "patch_apply_gated": { "method": "patch/apply_gated", "request": "PatchApplyRequest", "response": "PatchApplyResponse" },
    "taint_query": { "method": "analysis/taint_query", "request": "TaintQueryRequest", "response": "TaintQueryResponse" },
    "symbol_search": { "method": "analysis/symbol_search", "request": "SymbolSearchRequest", "response": "SymbolSearchResponse" }
  },
  "error_schema": "AgentErrorV1"
}
```

### 5.3 Agent UX Patch IR ↔ Quanta PatchArtifact 매핑

| Agent UX (Patch IR) | Quanta (PatchArtifact) |
|---------------------|------------------------|
| file operations (create/modify/delete) | SymbolEdit, TextEdit |
| hunks with ranges | AstSpanV1, TextEditKind |
| apply strategy | GateChain policy |

**변환 레이어**: Extension Host의 `tools/analysis/`에서 Patch IR → Quanta 요청 형식 변환.

## 6. 레포/패키지 구조 확장 ([RFC-010](../010.md) 반영)

### 6.1 Monorepo 배치

```
<repo_root>/
├── packages/
│   ├── vscode-agent-ux/        # FSD UI ([RFC-010](../010.md)). src/tools/ 포함
│   ├── agent-runtime/          # Orchestrator, ModelPort
│   ├── extension-host-mock/    # [RFC-009](../009.md)
│   └── quanta-bridge/          # 신규: Rust 엔진 연동
│       ├── src/
│       │   ├── server/         # HTTP/JSON-RPC 서버
│       │   ├── handlers/       # workset, patch, analysis
│       │   └── adapters/       # quanta-agent-layer 래퍼
│       ├── Cargo.toml
│       └── (semantica-codegraph-v2 의존: path 또는 git)
│
└── ../semantica-codegraph-v2/  # 외부 레포 (sibling)
```

**tools/analysis 위치**: `packages/vscode-agent-ux/src/tools/analysis/` ([RFC-010](../010.md) 3.1절)

### 6.2 quanta-bridge 패키지 (Rust)

- **역할**: quanta-agent-layer, quanta-adapters를 HTTP API로 노출
- **의존**: semantica-codegraph-v2를 `path = "../../semantica-codegraph-v2"` 또는 git submodule로 참조
- **실행**: Extension 활성화 시 API 서버 프로세스 기동, 또는 사용자 설정으로 외부 API URL 지정

### 6.3 tools/analysis (TypeScript)

- **역할**: Extension Host에서 quanta-bridge HTTP 클라이언트
- **위치**: `src/tools/analysis/` ([RFC-010](../010.md)의 tools/ 하위)
- **Tool 포트**: `AnalysisPort` 인터페이스, 구현체가 quanta-bridge 호출

## 9. 의존성 관리

### 9.1 semantica-codegraph-v2 참조

- **옵션 1**: git submodule (`git submodule add ../semantica-codegraph-v2`)
- **옵션 2**: 상대 path (`path = "../../semantica-codegraph-v2"`) — 단일 레포 통합 시
- **옵션 3**: published crate (quanta-agent-layer 등이 crates.io 배포 시)

### 9.2 빌드 순서

1. semantica-codegraph-v2 빌드 (`cargo build -p quanta-agent-layer`)
2. quanta-bridge 빌드 (quanta-agent-layer 링크)
3. Extension 패키징 시 quanta-bridge 바이너리 번들

## 10. Fallback 및 Mock

### 10.1 Quanta 미사용 시

| 상황 | 동작 |
|------|------|
| quanta-bridge 미기동 | analysis.* 도구 호출 시 `capability_unavailable` 에러. UI에 "분석 엔진 비활성" 표시 |
| 사용자 설정으로 비활성화 | analysis.* 도구는 no-op 또는 search.rg_search로 fallback (도구별 정책) |
| 연결 타임아웃 | [RFC-007](../007.md) retryable 에러, Recovery Panel에 "재시도" 옵션 |

### 10.2 [RFC-009](../009.md) extension-host-mock

- **analysis 포트 mock**: taint_query, symbol_search 등 fixture 기반 응답
- **patch_validate mock**: 항상 Approved 또는 configurable Rejected
- **gate-webview-standalone**: mock host에서 analysis.* 호출 시 fixture 응답으로 동일 렌더 검증

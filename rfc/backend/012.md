## 1. 목표

목적은 "모델 호출 추상화"가 아니라 **운영 가능한 모델 라우팅 계층을 SSOT로 고정**하는 것임.

ModelPort는 단순 wrapper가 아니라:

- **Task 기반 모델 선택**
- **계약 위반 시 자동 재시도 전략**
- **Provider 에러 표준화**
- **IR schema 강제**
- **Tool-call 강제 모드**

까지 포함하는 **Runtime Policy Engine**임.

## 2. Model Routing SSOT

### 2.1 schemas/agent-ux/policy/model-routing.v1.yaml

```
schemas/agent-ux/policy/model-routing.v1.yaml
```

```yaml
task_kinds:
  PLAN:
    preferred:
      - provider: openai
        model: gpt-4.1
    fallback:
      - provider: anthropic
        model: claude-3-opus
    constraints:
      temperature: 0.2
      max_tokens: 4000
      enforce_schema: PlanIR_v2

  PATCH:
    preferred:
      - provider: openai
        model: gpt-4.1
    fallback:
      - provider: openai
        model: gpt-4o
    constraints:
      temperature: 0.1
      enforce_schema: PatchIR_v2

  CHAT:
    preferred:
      - provider: anthropic
        model: claude-3-opus
    fallback: []
    constraints:
      temperature: 0.7
```

## 3. Provider Contract Normalization

### 3.1 model-provider-contract.v1.json

Provider-specific 에러는 전부 아래 타입으로 환원.

| 에러 코드 | 설명 |
|----------|------|
| MODEL_TIMEOUT | 호출 타임아웃 |
| MODEL_RATE_LIMIT | Rate limit 초과 |
| MODEL_SCHEMA_VIOLATION | IR schema 검증 실패 |
| MODEL_PROVIDER_ERROR | Provider 내부 에러 |

위 계약은 `schemas/agent-ux/contracts/model-provider-contract.v1.json`에 정의.

---

## 4. Schema Enforcement Loop

### 4.1 모델 응답 처리 단계

1. Raw output 수신
2. JSON parse
3. IR schema validation
4. 실패 시:
   - schema violation prompt 자동 삽입
   - 최대 2회 재시도
   - 2회 실패 시 hard fail

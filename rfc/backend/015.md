## 1. 목표

**제품급 SOTA++**가 아니라 **엔진급 SOTA+++ Agent Runtime 아키텍처**로 잠금.

| 목표 | 설명 |
|------|------|
| Deterministic Replay | event log replay로 상태 복원 |
| Partial Resume | 중단 지점부터 재개 |
| Model Drift 흡수 | capability profiling 기반 라우팅 |
| Tool Non-determinism 통제 | sandbox, metadata SSOT |
| Concurrency 안전 | Single Writer Rule |
| Trajectory Regression | CI에서 golden trajectory 검증 |
| VSCode/Standalone/Web 동일 Runtime | Runtime 독립 모듈 |

---

## 2. Runtime Layer Architecture v3

Agent = 단순 LLM 래퍼가 아님. **6 Layer**로 고정:

| Layer | 역할 |
|-------|------|
| **Session Kernel** | State Machine Core (결정적) |
| **Model Runtime** | Routing + Contract Enforcement |
| **IR Compiler** | Prompt → IR → Validated IR |
| **Tool Execution Sandbox** | sideEffect, idempotent, reversible |
| **Artifact Bus** | Blob + Snapshot SSOT |
| **Evaluation & Replay Engine** | Deterministic replay, trajectory regression |

### 2.1 Runtime Layer Diagram

```
User Intent
   ↓
Session Kernel
   ↓
Model Runtime
   ↓
IR Compiler
   ↓
Execution Orchestrator
   ↓
Tool Sandbox
   ↓
Artifact Bus
   ↓
State Update
```

---

## 3. Session Kernel (결정적 상태머신)

SOTA급 Agent는 반드시 **상태머신 기반**.

### 3.1 상태 정의

```
IDLE | ANALYZING | PLANNING | AWAITING_APPROVAL | EXECUTING | VALIDATING | RECOVERING | FAILED | COMPLETED
```

### 3.2 Transition Contract

- 모든 transition은 **event 기반**
- event는 **append-only log**
- state는 **log replay로 복원 가능**

```
event_log/
  0001_user_prompt.json
  0002_plan_generated.json
  0003_patch_preview.json
  0004_patch_applied.json
```

이 구조로: deterministic replay, audit, trajectory regression 가능.

---

## 4. Deterministic Replay Engine

SOTA+++ 필수 요소.

### 4.1 Replay 모드

| 모드 | 설명 |
|------|------|
| **Model Mock Mode** | 모델 출력 고정 fixture 사용. CI gate용 |
| **Tool Mock Mode** | tool 결과 고정 |
| **Full Re-run Mode** | 실제 모델 + 실제 tool |

CI에서는 **Model Mock Mode**로 gate 통과.

### 4.2 Drift Detection

Replay 시 다음 중 하나라도 다르면 FAIL:
- IR mismatch
- tool sequence mismatch
- artifact hash mismatch

---

## 5. IR Compiler v3 (Schema + Semantic Guard)

### 5.1 2단계 검증

1. **JSON Schema validation**
2. **Semantic validation**

예:
- PatchIR에 `revert_diff` 없으면 reject
- HIGH risk step인데 `approval_required=false`면 reject

---

## 6. Tool Execution Sandbox

SOTA+++에서 제일 위험한 부분.

### 6.1 Tool Metadata 필수 필드

```typescript
type ToolMetadata = {
  id: string
  sideEffect: "READ" | "WRITE" | "EXEC"
  idempotent: boolean
  reversible: boolean
  dryRunSupported: boolean
  riskLevel: "LOW" | "MEDIUM" | "HIGH"
}
```

### 6.2 Sandbox 원칙

| 원칙 | 내용 |
|------|------|
| WRITE | 반드시 preview 제공 |
| EXEC | 승인 없이는 실행 불가 |
| 결과 저장 | 모든 결과는 ArtifactBus로 저장 |
| Cancel | tool은 cancel token 필수 지원 |

---

## 7. Artifact Bus (Blob + Snapshot SSOT)

모든 모델 응답, IR, patch diff, tool 결과, 테스트 로그는 **hash 기반 저장**.

```
artifact/
  sha256_xxx.json
```

PlanIR에는 artifact ref만 남김. 재현성, 대용량 안전, 디버그 가능.

---

## 8. Concurrency Model

### 8.1 Single Writer Rule

- Session Kernel은 **단일 writer**
- Tool 실행은 병렬 가능하지만:
  - state update는 단일 thread
  - event append는 atomic

### 8.2 Conflict Model

동일 파일 동시 patch 시:
- optimistic apply
- conflict 발생 시 **RECOVERING** 상태 전환

---

## 9. Recovery Engine

에러는 실패가 아니라 **새로운 Plan 생성 트리거**.

**Flow**:
1. Tool 실패
2. Error normalize
3. Recovery prompt 생성
4. New PlanIR 생성
5. 기존 state와 merge
6. Recovery 성공하면 trajectory PASS

---

## 10. Evaluation Engine v2 (Trajectory Regression)

### 10.1 Golden 정의

- Tool sequence
- Patch semantic equivalence
- Artifact hash
- **모델 문장 일치 불필요**

### 10.2 Patch Equivalence

단순 diff 비교 금지.

- **AST equivalence**
- formatting 차이 무시
- import reorder 허용

---

## 11. VSCode / Web 통합 구조

```
VSCode Extension
   ↓
Agent Runtime (WebWorker)
   ↓
Session Kernel
```

- Extension은 **UI만** 담당
- Runtime은 **독립 모듈**
- VSCode 없이도 실행 가능 (Standalone, Web)

---

## 12. Model Drift 대응 전략

### 12.1 Capability Profiling

각 모델에 대해 자동 수집:
- schema violation rate
- tool hallucination rate
- avg plan length
- recovery frequency

Routing 정책은 **통계 기반**으로 갱신.

## 14. SOTA+++ Claim 조건

다음 충족 시 주장 가능:

- [ ] IR이 reversible contract임
- [ ] runtime이 deterministic replay 가능
- [ ] golden trajectory regression CI에 있음
- [ ] patch semantic equivalence 검사 있음
- [ ] provider 에러 표준화됨
- [ ] tool sideEffect SSOT 존재
- [ ] recovery path regression 있음
